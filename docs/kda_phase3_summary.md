# KDA on gfx936：第三阶段（全局优化收口）总结与方法论（2026-10-16 ~ 10-17）

## 0. 范围与约束

- **目标**：把 KDA（Kimi K3 训练算子）在 Hygon BW1000（gfx936）上做到极致，并形成一套可复用的系统方法论。
- **三条约束**：
  1. 结果逐位一致：每次改动都要对照合入前的版本，通过 GATE_ALL 与 FI=3 门禁；
  2. 不改算法；
  3. 前向留给反向的显存不超过 FLA 默认（1032 B/token·head），这是用户 10-16 批准的上限。
- **同步范围**：hip_kda（Megatron-LM-das / K3 走这条）和 flash-train。flash-train 的对外接口保持不变（决定 C）；需要改接口的项，留到 V2 和 P-77b 一起评审。

## 1. 结果

### 1.1 时间线（16K/TP8，一次前向+反向的设备时间）

| 时间点 | 设备时间 | 对 H20 FLA 默认 | 对 A800 FLA 默认 |
|---|---:|---:|---:|
| 10-10 首次跨平台对比 | 7.86 ms | 0.66 | 0.95 |
| 10-12 首次与 H20 对比 | 6.75 | 0.76 | 1.10 |
| 10-16 本阶段开始（P-65） | 6.36 | 0.81 | 1.17 |
| **10-17 本阶段结束（P-88）** | **5.61** | **0.92** | **1.33** |

本阶段 16K/TP8 快了 13%。16 个形态（8K–64K × TP1/2/4/8）相对本阶段开始的提速为 1.10–1.23 倍，TP1 最大（主要来自 P-88）。这是用离散度 ≤ 3% 的快卡数据跨会话比较得出的；各项改动自身的收益，都是在同一会话、同一张卡上交替测量的。

### 1.2 三平台（P-88，16 个形态，设备时间，`results/kda-xplat-3way-20261017/tables_p88.md`）

| 对手 | 区间 | 几何平均 | 9 个重点形态（16K–64K，TP>1） |
|---|---:|---:|---:|
| A800 FLA 默认 | 1.12–1.48 | **1.25** | 1.29 |
| A800 FLA 最快（关重算，显存约 3 倍） | 1.01–1.30 | 1.13 | — |
| H20 FLA 默认 | 0.79–1.03 | **0.875** | 0.907 |
| H20 FLA 最快 | 0.71–0.90 | 0.78 | 0.81 |

64K/TP8 已经超过 H20（1.03）。为什么能赢 A800、赢不了 H20，详细论证见 `results/kda-xplat-3way-20261017/why_a800_not_h20.md`。

## 2. 本阶段做了什么

### 2.1 合入的改动（全部逐位一致；hip_kda 三台机器合入，涉及 kernel 的同步到 flash-train）

| 编号 | 内容 | 前向+反向的收益 |
|---|---|---|
| P-77b | 前向直接存 qn/kn，反向省掉 l2n_apply | 1.5–1.7% |
| P-82 / 82b / 87 | 前向保存 h，wu 顺带算 v_new，反向省掉重算递推（H ≤ 48，显存等于 FLA 默认） | TP8 3.4–4.0%，TP4 2.9%，TP2 2.0–5.2% |
| P-83 / 83b | s4a 把读取全部提前发出，AFS 复用 A 块 | 0.9–1.4%，再加 0.7–1.1% |
| P-84b / 84c | wu 的 phase 1 先发出读取；phase 3 复用 exp2f(g) | 0.3–0.6%，再加 1.6–1.8% |
| P-85 | dhu 在 192 个 CTA 时改用 8-wave 版 | TP2 0.6–0.8% |
| P-88 | s4a/s4b 改为 head 维变化最快的 grid 顺序 | TP8 2.8%，TP2 6.8%，**TP1 16.5–18.8%** |

flash-train：`82f29f5`、`9a41967`、`a1e0e35`。P-77b、P-82 需要改接口，留给 V2。

### 2.2 证伪或否决的方向（都有实测数据）

| 方向 | 结论 | 依据 |
|---|---|---|
| 把 l2n 合进多个使用方（P-77） | 0.990–0.997 | 同一份计算要在多个 VALU 已经吃紧的使用方里重复做（R57） |
| 按段融合（s4b+tail、prep_a+prep_b） | 盈亏平衡或负收益 | 必须降到每 CU 1 个 CTA：s4b +355 µs、prep +565 µs（P-78）；完全去掉屏障的上限仍有 +229 µs（P-79c） |
| 去掉 Wb 副本（P-80a） | 净负收益 | wu 省 42–166 µs，dhu 的转置多 70–327 µs |
| 只改 wu 中 VNEW 的读取（P-84） | 无收益 | 等待点判断错了（R58） |
| 其它 kernel 也改 grid 顺序（P-89） | wu 0.67–0.95，prep 0.76–0.93 | grid 顺序必须按 kernel 逐个实测（R60） |
| prep_a 提前读 beta（P-90） | 无收益 | prep_a 受 VALU 限制，那些等待本来就被盖住了 |
| 更宽的访存指令 | 0 | 访问已经合并时，代价只看字节数（`ta_width.hip`） |
| s4b 调整读取顺序（P-79 OT2） | 0 | 等待点消失了，但等待转移到别处，每个 wave 的总周期不变 |
| 部分改走 LDS-DMA（P-91） | s4b 快 2%，总体 0.4% | 所有显存操作共用一个按顺序计数的 vmcnt，编译器的等待会把 DMA 一起等完（R61） |
| 全异步 LDS-DMA 流水（P-92） | 每 CU 1 个 CTA 的代价从 +39% 降到 +30% | 每个 SIMD 只有一个 wave 时，LDS、指令依赖和发射的延迟都暴露出来（R62） |
| kp 布局推广到 H=48 | 只比 P-87 多 0.4–1.1% | 需要改 6 处并加编译宏隔离 flash-train，投入产出比低，暂缓 |

## 3. 方法论（在第二阶段的基础上补充）

### 3.1 一轮优化的循环

1. **量**：
   - 字节账目：实测 HBM 字节、接口字节、算法必需字节（`byte_ledger.py`）；
   - 每个 kernel 的上限卡：访存、TA、VALU、MMAC、递推串行链几项下限取最大值，再和接口下限比（`ceiling/cards.py`）；
   - 三平台对比（`xplat3_report.py`、`h20_gap.py`、`h20_bytes.py`）。
2. **找最大的那块差距**：按“kernel 实际时间 − 资源下限”和“资源下限 − 接口下限”两层分别排序。并且**比较同一个 kernel 按 head 数折算后的耗时**，看它是否随 H 上升（R60）。
3. **诊断到源代码行**：先抓 SQTT，再用 `map_waits.py` 对到源代码行（R58）；访存指令清点用 `vmem_census.py`。
4. **先测上限，再动手**：用消融或探针把可得收益的上限测出来，比如 P-78 的降占用率、P-79c 去屏障、P-80a 的转置代价。
5. **实现**：用环境变量或模板开关做探针，先过逐位门禁，再在同一进程或同一张卡上交替 A/B。
6. **合入或否决**：合入的话，hip_kda 三台机器加 flash-train 一起同步；否决的话，记录数据并写成规则。

### 3.2 本阶段新增的规则

- **R57**：把一个生产方合进多个使用方，它的计算会被重复多份，即使省了字节也可能更慢。
- **R58**：根据 SQTT 等待点设计探针之前，必须先把等待点对到源代码行。
- **R59**：同一个循环里既读显存又写显存、指针没有 `__restrict__` 时，编译器会把每一轮的读取串行化；应该先单独发出所有读取。
- **R60**：grid 顺序（哪些 CTA 同时驻留）决定 DRAM 和 TLB 的访问局部性，是一个独立的调优维度。
- **R61**：gfx936 的 LDS-DMA 能用，但它和其它显存操作共用一个按顺序计数的 vmcnt；只把一部分读改走 DMA，拿不到异步效果。
- **R62**：在 gfx936 上，“每 CU 只放 1 个大 CTA”的融合思路基本不划算；要融合，就必须保证每个 SIMD 上至少有 2 个 wave。

### 3.3 测量规范（本阶段踩过的坑）

- bw52 的 HCU2、HCU4 比其它卡慢约 10%；主机上有一个占满一个核的 root `cat` 进程，会干扰墙钟时间。
- 同一张卡在不同会话之间，绝对时间会差 ±5–9%。跨版本比较必须在同一会话、同一张卡上交替测量；跨平台的绝对值要用离散度 ≤ 3% 的数据。
- 机器经常被其它用户占用：bw46 的 HCU6/7，bw47 和 bw52 时常被整机占满。每次测量前都要看 `hy-smi --showuse`；`--showmemuse` 只能看显存占用，不够用。
- A800 上 FLA 的数据跨会话复测，差异在 ±0.4% 以内，可以复用。

## 4. 剩余空间（在三条约束下）

- **各 kernel 资源下限之和**：16K/TP8 是 4.87 ms（P-87），比 H20 只快 6%；TP2 与 H20 大致持平。即使每个 kernel 都压到自己的下限，也就到这个水平。
- **还没细查的**：TP2 下 wu 约 0.8 ms、前向 MODE 5 约 0.6 ms（访存指令发不出去），这两块的上限是让 TP2 接近与 H20 持平。
- **结构性的瓶颈**：实测字节是算法必需量的 5.86 倍，其中 4.12 GB 是 kernel 之间交接的接口字节。降不下来，是因为：
  - 片上放不下（64 KB LDS、8 MB L2）；
  - 单个 SIMD 一个 wave 时掩盖不住延迟（R62）；
  - 逐位一致的约束（交接数据要用 fp32）。

## 5. 放开约束之后的选项（只评估，没有合入；详见 `results/kda-gfx936-20261017-p93-b16handoff/README.md`）

| 选项 | 放开的约束 | 精度（S2 判据：不超过 FLA 误差的 1.10 倍） | 收益（前向+反向） | 对 H20 比值的估计（16K/TP8，16K/TP2） |
|---|---|---|---:|---:|
| **B1′**：s4b 交给 tail 的 dq/dk 改用 bf16 | 逐位一致 → 不差于 FLA | **PASS**：dq/dk 是 FLA 的 1.05–1.06 倍，其余与生产版相同 | TP8 2.6%，TP2 3.2% | 0.92 → 0.94，0.84 → 0.87 |
| B1：dq/dk/dg 都改用 bf16 | 同上 | **FAIL**：dg、ddt_bias、dA_log 是 FLA 的 1.6–2.6 倍 | 4.7–5.2% | — |
| B2：g 改用 bf16 | 同上 | 从原理上不可行：g 的量级约 320，bf16 步长 1–2，exp2 后相对误差约 100% | — | — |
| C：改算法，缩小每个 chunk 的工作集 | 不改算法 → 允许改 | 需要先推导、再做数值研究 | 未知 | — |
| A：每个 CTA 8 个 wave，再叠加全异步流水 | 无（只是大改 kernel） | 逐位一致 | 不确定；仍受 64 KB LDS 限制 | — |

**收口结论**：
- 在三条约束下，KDA 在 gfx936 上已经接近当前拆分方式的上限：对 A800 FLA 全面领先（几何平均 1.25 倍），对 H20 FLA 是 0.79–1.03。
- 剩下的差距，主要来自 H20 带宽是 BW1000 的 2.85 倍，以及 gfx936 片上容量和每 SIMD 单 wave 时掩盖不住延迟所带来的结构性限制。
- 如果用户接受“不差于 FLA”这条精度判据，B1′ 可以再拿到约 3%。要想明显超过 H20，需要走算法层面的改动（C）。
