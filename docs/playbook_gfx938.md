# HCU 算子优化方法论 · gfx938 分册（BW1102，2026-11-03）

本分册只记录 **gfx938** 上的卡特性、优化思路和路线。通用方法论（四个下限、每轮三问、判停、度量）见
`playbook.md`；gfx936 的特性与路线见 `playbook.md` 第 11 节的 gfx936 小结和 `kda_mk3_round.md`。
两张卡的数字和规则**不可互换**：同一个改法在两张卡上结论可能相反（例：打包 fp32、16 KB 布局、MLS）。
gfx938 的全部实验记录在 `kda_gfx938_round.md`（§1–§138），本分册是它的提炼。

## 1. gfx938 的卡特性（实测，nmz5）

| 资源 | gfx938 实测 / 结论 | 对设计的含义 | 出处 |
|---|---|---|---|
| CU / 频率 | 72 CU，约 1.3 GHz | 小网格（≤ 288 CTA）容易出现波次量化 | §83–84 |
| VALU | 相对 gfx936 弱约 22%，相对 H20 只有 0.3–0.6x | VALU-bound 的 kernel（prep_a、bwd_tail）是前向/反向的软肋 | §53、§58 |
| 矩阵单元 | 相对 H20 约 2.4x；原生 MMAC builtin（`__builtin_hcu_mmac_*_lit_lts`） | 富裕资源；lit/lts 只改 C 的布局（输出是置换，逐位一致） | §86、§123 |
| HBM | 高于 gfx936，约为 H20 的 0.46x | 交接流量比 gfx936 便宜，但仍是 prep_b / fwd_h 的墙 | §76 |

## 2. gfx938 上的优化思路（与 gfx936 的差异）

1. **先查驻留限制是哪一个资源**：按 768 VGPR 预算和 LDS 档位（16 / 21.3 / 32 KB）算每个 kernel 的实际 CTA 数，
   再决定压 LDS 还是压 VGPR。压 VGPR 到 128 / 168 几乎总是溢出变慢（0.32–0.89x），压 LDS 到 16 KB 往往值钱
   （prep_a 小网格 1.25–1.28x）。
2. **VALU-bound 的 kernel 先做打包 fp32**：按列成对、`fma(b, -1, a)` 做减法、负值形式保存补偿项；exp2 / rcp 逐元素。
   bwd_tail 1.09–1.22x，prep_a 1.03–1.06x。注意 VGPR 上涨可能丢 CTA（先算档位）。
3. **矩阵单元富裕，但"把元素级工作挪到 MMAC"需要重结合**，过不了逐位门禁；放宽数值要过 FP64 / FLA 误差线
   （bf16 表格 1.75–3.7x 超标被否）。
4. **交接比 gfx936 便宜，融合不一定赚**：prep_a + prep_b 融合在 16 KB 上仍 0.83–0.86x（两段延迟相加）；
   重新切分 prep 也不划算。只在融合后 CTA 数不降、且两段能重叠时才考虑。
5. **全局访问保持 lane 有序（R69）**；需要的置换放到 LDS / 生产者布局 / `ds_bpermute`。
6. **地址改写只对 VALU / 递推 kernel 有效**：TA-bound 的 s4a / dav 改成 SGPR 基址 + 32 位偏移无收益。
7. **只计时的上限变体也必须先过门禁**：越界的 LDS 访问会被丢弃，给出虚假的加速（§130）。

## 3. KDA 在 gfx938 上的路线与现状（截至 2026-11-04，flash-train `079f58b`）

- 已保留（gfx938-only 路径，gfx936 逐位不变且无回归）：P-938sa、P-938pk / pk2（bwd_tail、prep_a 打包）、
  P-938va（v_new A 形交接）、P-938a16（prep_a 16 KB）等；相对 `5ebce6f` 24 形态总耗时 1.021x。
  之后 P-938bc2（dav 第 2 段 LDS 交错）+ P-938bc4（wu 五段 LDS 布局）：冲突 dav 1920→384、wu 4096→1280（小网格 8704→768）/CTA，
  dav 1.03–1.11x、wu 1.01–1.09x，9 形态 fwd+bwd 1.001–1.017x（几何平均 1.006）；24 形态（BW1300，p8c 节点，§152）
  总耗时几何平均 1.0065，24/24 ≥ 1。nmz5 自 11-03 晚被外部 rccl 任务占满（§151），计时改在 p8c 节点（BW1300，64 CU）上做。
- 对 H20 FLA：总耗时约 1.00–1.03，前向约 0.90–0.94，反向约 1.04–1.06。差距在前向，主要是硬件 VALU / SFU 吞吐；
  FLA 的 chunk 算法与我们同类（因子化衰减、子块参考、分块求逆），C = 32 / 128 都省不到 25%（§137–138）。
- 已否定（gfx938 上）：A1（s4a / dav 地址）、bwd_tail 3 wave、Kb chunk 连续布局、B1（dhu 双缓冲）、
  B2（dhu lit1 lts1）、s4b 行切片预取、s4b 第三个 CTA（P-938s1 拆分 / dwT 预取）、s4a 16 KB（VGPR-bound）、
  prep 融合、s4b bf16 表格。
- 全链账本（§139，8192/64）：每次 fwd+bwd 搬运 11.4 GB，平均 1.0 TB/s（约峰值 53%），纯流量下限约 6.0 ms 对实测
  11.35 ms；约 85% 的字节是 kernel 间交接。s4b 42%、dhu / fwd_h 45–46%、prep_a VALU 0.77、wu / dav 有明显 LDS bank conflict。
- 交接字节表（§145，8192/64）：内部交接 8.7 GB，理论最少 4.8 GB；已测关闭或被驻留/LDS 卡住约 2.5 GB，仍开放约 1.3 GB：
  wu 自算 g（0.8 GB）、dav 并入 dhu / dhu 直读 do（dVn + dOT 0.4 GB）、AqkA（0.13 GB）；均需先做删除上限。
- 2026-11-04 新保留：P-938cg（wu 第 1 段的 exp2f(g) 留给第 3 段，不再重读 g；wu 1.08–1.11x，fwd+bwd 几何平均 1.010）、P-938os（fwd_h 宽版 o 暂存块 XOR 交错，冲突 704→128/步；H=64 时 fwd_h 1.02–1.04x）；gfx936 逐位一致、无回退（§153–156）。
- 2026-11-04 回到 nmz5（BW1102，已空闲）：079f58b 对 2631309 24 形态总耗时几何平均 1.0145（22/24 ≥ 1，§157）。s4b 第三个 CTA（P-938s3：LDS 20224 B，wave 内交换自有表块）逐位一致但计时有涨有跌（大网格 +2–10%，256 CTA 网格 −5–9%），未保留（§158）。
- s4b 3-CTA 实例按网格启用（P-938s3r，§159）：VGPR 压不下来（加上限即溢出）；按网格挑选的版本逐位一致，但在 H=64 形态上和先前宏版本测得结果相反（2048/64、8192/64 变慢），原因未查明，未保留。
- 2026-11-04 上限测量（§148–149）：dav 第 2 段并入 dhu 关闭（dhu 侧 0.42–0.61x，dav 能省的只有 0–9%）；dOT 单独去掉 ≤0.6%；wu 改读 bf16 g 无收益（0.95–1.03x，g 读取按指令/延迟计费而非字节）。交接表已无 ≥1% 的项。
- 待做（按 gfx938 特性重新审视）：s4b 第三个 CTA（LDS 清单 + bank 模型）；wu 第 3 段 g 重读（≤0.8%）；wu 自然行改 144 short 节距（u-MMAC 512→0）；
  s4b 第三个 CTA（还差约 1.45 KB LDS）、dhu 转置写出、fwd_h 瓶颈、后向 gate kernel、AqkA 重复写出、
  小 T 的启动与波次开销。

## 4. gfx938 规则（R67 起，来自 `kda_gfx938_round.md`）

| 规则 | 内容 |
|---|---|
| R67 | SQTT 给某段指令记的占比不等于删掉它能省的时间（s4a 的写出记 9.3%，删除只省约 3%）：以删除上限为准 |
| R68 | SGPR 基址 + 32 位字节偏移只对 VALU / 递推 kernel 有效（bwd_tail、dhu、wu、prep_a），TA-bound 的 s4a / dav 无收益；逐 kernel 实测 |
| R69 | 递推 kernel 的 16 B 全局读取保持 16-lane 组内 lane 有序 |
| R70 | 驻留：约 768 VGPR / lane / SIMD；4 CTA 要 LDS ≤ 16 KB 且 VGPR ≤ ~176 |
| R71 | 只计时的上限变体也先过门禁（越界 LDS 访问被丢弃） |
| R72 | 打包 fp32：减法写成 `fma(b, -1, a)`、取负折进补偿项，否则后端拆成标量 |
| R73 | MMAC lit1 lts1 / lit1 lts0 与 lit0 lts0 的输出是置换，逐位一致；但改布局不等于省时间 |
| R74 | LDS 布局改动前先分段定位冲突（skip-mask 构建 + hipprof），并用指令形式的模式微基准拟合 bank 模型；只拟合 kernel 自身计数的模型可能碰巧吻合（bc3 预测 768、实测 3328） |
| R75 | 往递推 kernel（dhu / fwd_h）里搬活不因其 VALU / MMAC 空闲而免费：它们按每步 VMEM 发射定节奏，每步多一条读（哪怕 L2 命中的标量 gather）都落在链上（A1：dhu 0.42–0.61x） |
