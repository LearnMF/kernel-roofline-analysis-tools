# B 类（会改变数值）候选的精度与性能评估（2026-10-13）

**验收规则 R23b**：
1. 确定性：同一输入重复运行，结果逐位相同；
2. 对 FP64 oracle 的精度不比生产版差：17 组多 seed 配对，每个张量 rms_ratio 的几何均值 ≤ 1.01，且单侧符号检验不显著变差；
3. 不超过 PR #556 的容差，并且不比 FLA 差 10% 以上；
4. Megatron 的 loss 曲线与基线对齐（单独验证）。

**工具**：
- oracle：冻结的 `reference_kda.py`（来自 PR #556，FP64）；
- 门禁：`bclass_gate.sh` 和 `bclass_report.py`。在 bw7 上跑，生产树是 P-54a，指纹 `90a91fdd5fdd`。

## 1. 之前已评估的：fp32 中间结果改窄格式交接（`results/kda-hq-precision-20261013/`）

| 变体 | 精度 | 实际性能收益 | 结论 |
|---|---|---|---|
| dq/dk/dg 改 bf16 | dt_bias 误差是生产版的 3.3 倍，g_raw 2.0 倍，A_log 1.5 倍；比 FLA 也差 1.5–2.6 倍 | 约 1.5% | 否决 |
| dq/dk/dg 改 fp16、dAqk 改 bf16 | 违反规则 2（比生产版差 0.1–8%），满足规则 3b；fp16 还有下溢风险 | 约 1.5%：相关 kernel 受 TA 或发射限制，字节减半但指令条数不变（R36） | 否决 |

更正：我之前引用的“TP2 上 5–10%”是只按字节估算的旧数字，实测估算只有约 1.5%。

## 2. 本轮：bf16 舍入方式（P-56，`examples/kda/p56_round.py`）

生产版的手写转换 `bf_rne` 是 RNE：`u += 0x7fff + ((u>>16)&1)`，每个元素需要 v_bfe_u32 和 v_add3_u32 两条 VALU。

| 候选 | 改法 | 舍入相关指令（整个 kernel） |
|---|---|---|
| **rhu** | `u += 0x8000`：四舍五入，平局时远离 0，每个元素 1 条指令。只有低 16 位恰好是 0x8000 时才与 RNE 不同 | wu 2210→1948，prep_a 3515→3313，s4a 589→536，dhu4 主循环 219→199 |
| **rz** | 直接截断，不做舍入 | wu 2210→1689，prep_a 3515→3153，s4a 589→468，dhu4 主循环 219→175 |

### 性能（bw52，每边 5 个进程，带显存位置抖动；比值为生产版 / 候选，> 1 表示候选更快）

| 形态 | rhu 算子 | rz 算子 | rz 关键 kernel |
|---|---:|---:|---|
| 16K/12 | 1.0066 | **1.0235** | 前向递推 1.082，重算 1.072，prep_a 1.064 |
| 16K/48 | 1.0054 | 1.0080 | 重算 0.975（R21：去掉 VALU 后，读取挤在一起发射） |
| 64K/12 | 1.0052 | **1.0209** | 前向递推 1.070，重算 1.081 |
| 8K/96 | 1.0004 | 1.0002 | 重算 0.924 |

### 精度（bw7，规则 1–3）

| 候选 | 结果 | 详情 |
|---|---|---|
| rhu（17 组配对） | 规则 1–3 都**通过，但卡在边界上** | o/dq/dk/dv 的几何均值 ≤ 1.0002；g_raw 1.0075（17 组中 12 组变差，p = 0.072）；**dt_bias 1.0100**（12/17 变差，p = 0.072），正好压在 1% 的门槛线上。比 FLA 好（dt_bias 中位数是 FLA 的 0.81 倍） |
| rz（前 6 组配对后停止） | **全部失败** | 所有张量的误差都是生产版的 3.0–4.4 倍、FLA 的 3.5–4.1 倍；o 超出 PR #556 的容差 |

**原因**：
- 截断每次都把数值往 0 的方向偏半个 ulp，这种偏差在递推状态和归约型梯度里同向累加，不会相互抵消。
- rhu 只在平局时与 RNE 不同，但平局比预想的常见：两个 bf16 相乘的结果只有 16 位有效尾数，低 8 位全是 0，所以低 16 位恰好等于 0x8000 的概率约为 1/256，而不是 2⁻¹⁶。dt_bias 和 A_log 又要把 T×K 个元素加起来，“平局时远离 0”的偏差就在这里显现出来。这与 P-26 和 R25 的结论一致。

## 3. 其余 B 类候选

| 候选 | 判断 |
|---|---|
| C2：预先算好 qgᵀdO | 预处理阶段要多写、多读 P，每 token·head 512 B，wu/prep 受吞吐限制，会把 dhu 每步省下的时间抵消掉；净收益约 0 |
| C3：用 MMA 求对角块的逆（MXR / FROST 的做法） | 只影响 prep_a 的一部分 VALU，收益约 0.5–1%；按 Huawei 论文的结论，还必须加迭代修正才能保住精度 |
| 改变 K 的顺序，省掉 LDS 转置（R44） | 递推里 LDS 的主要作用是在 wave 之间交换数据（GEMM 的输出行分散在不同 wave 上），不只是转置；改变 K 的顺序省不掉这一步 |

## 4. 结论

- 所有 B 类候选里，**精度过得去的，收益都不到 1%**（rhu 0.04–0.66%，窄格式交接约 1.5% 但违反规则 2）；**收益最大的截断（TP8 +2.1–2.4%）精度直接崩掉**。
- 舍入方式和中间精度都卡在精度这一关上。原因在于 KDA 的 dt_bias、A_log、g_raw 是对整条序列归约得到的，对系统性的舍入偏差高度敏感。
- **B 类方向关闭**。rhu 理论上可以合入（规则 1–3 通过），但它把 dt_bias 推到门槛线上，换来的不到 0.7%，按 R23（精度优先）不建议合入。
