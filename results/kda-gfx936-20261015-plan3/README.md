## 候选（按“绝对缺口 × 可做性”排序）
1. **P-72：tail 的 phase B 改为每条指令处理两行。** lane 0–31 处理第 r 行，lane 32–63 处理第 r+1 行，每个 lane 负责相邻 4 列。dy 用一条 dwordx4 读、y 用一条 dwordx2 读、结果用一条 dwordx2 写，phase B 的 VMEM 指令减半。行内点积仍按生产版的固定顺序树计算：生产版第 1 级 off=1 求和 p_2j + p_2j+1，正好等于本方案中一个 lane 内的 pa + pb；后面 5 级在 32 组之间按组号的二进制位配对，本方案对应 32 个 lane 的 off = 1..16。浮点加法满足交换律，所以结果逐位一致。
2. **tail 的 phase A 同样改为每条指令处理两行。** 难点是按列顺序做扫描，需要重新分配 wave 和行块。
3. **prep_b：88 条 dword 读。** R scratch 每个 lane 4 B，由 prep_a 写出、prep_b 读入，属于内部交接，可以同时改写读两端的映射。
4. **s4b：**
   - gn 那一行对所有 lane 相同，可以改用标量读（SMEM），每个 wave 少 8 条 TA 指令；
   - k、q 每次只读 32 B 段，可以经 LDS 暂存后合并成宽读；
   - 开头那些转置标量读，P-57 已经测过，收益 0.2–1%。
5. **prep_a：** 受 VALU 限制，主要的 fp 指令都被逐位约束锁定，可改的只剩地址和 mov 两类。

## P-72 结果（bw46，2026-10-15）：逐位一致，但变慢，**不合入**
- **第一版**：dq/dk 约 100 个元素差 1 ulp，原因是 lane 映射改了之后，编译器的打包向量化方式也变了，fma 融合随之不同。生产版 ISA 里，dot 用 `v_pk_mul` + `v_add` 计算（不融合成 fma），输出是 `pk_fma(dy, r, -((dot·y)·r))`。第二版用 `#pragma clang fp contract(off)` 加显式 `__builtin_fmaf`，按这个顺序逐条钉住，逐位门禁 10/10，FI=3 PASS。
  - **新规则 R53**：改 lane 映射时，要把生产版 ISA 的浮点运算顺序（mul/add/fma 的组合）逐条钉住，否则编译器的打包与融合方式变化会破坏逐位一致。
- **A/B**（tail 单 kernel）：

| 形态 | 比值 |
|---|---:|
| 16K/12 | 0.983 |
| 64K/12 | 0.973 |
| 16K/48 | 0.971 |
| 8K/96 | 0.975 |

  VMEM 指令数减半，tail 反而慢了 2–3%。
- **结论（新规则 R54）**：在 gfx936 上，对已经合并良好的行访问，把 dwordx2 换成 dwordx4（总字节不变）不会减少 VMEM 发射受阻；TA 的占用随字节数和访存延迟变化，与指令条数无关（与“TA 在整个取数过程中都被占住”的微基准结论一致）。体检卡里“VMEM 指令倍数”“TA 放大”这两个指标会高估加宽访存的收益。TA 受限的 kernel，能动的只有**字节数**（重复读取、scratch 往返）和 L2 命中率。
- **据此重排候选**（多余字节 = 实测 − 接口必需）：
  - s4b：+239 MB（972 vs 733）；
  - prep_a：+138 MB；
  - prep_b：+127 MB（R scratch 往返，实测 358 MB vs 必需 231 MB）；
  - s4a：+115 MB；
  - tail：+33 MB，已接近字节下限，不再优化。
