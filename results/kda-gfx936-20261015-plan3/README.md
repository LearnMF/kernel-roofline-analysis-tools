# 方案 3：按 chunk 并行 kernel 的资源归因（TP8 16K/12，生产版含 P-65，2026-10-15，bw46）

数据来源：
- 体检卡：`../kda-ceiling-cards-20261013/cards.md` 的 16K/H12 一节（P-52 时期）。此后这些 kernel 只有 wu、prep_a、prep_b 做过 kp 置换，s4a、s4b、tail 未改。
- 生产二进制的 ISA：用 `extractkernel` 从 `_G2*.so` 抽出，静态分类脚本为 `examples/kda/isa_cat.py`。
- SQTT 等待位点归因：`examples/kda/blocks/cap_k.sh` + `sqtt_hotspots.py`，结果在 `sqtt/*.txt`。

各 kernel 的 VALU 构成（静态指令数）：
- **prep_a**：fp 1986（其中 `expf` 展开约 33 组、IEEE 除法 42 组；受数值逐位约束，不能改）、int 863、bf16 舍入 362、64 位地址 196、mov 295。
- **s4b**：64 位地址 696（占 VALU 的 22%）、mov 447、int 1044。
- **tail**：fp 2495（Kahan 补偿与 shfl 树）、64 位地址 770。

## 候选（按“绝对缺口 × 可做性”排序）
1. **P-72：tail 的 phase B 改为每条指令处理两行。** lane 0–31 处理第 r 行，lane 32–63 处理第 r+1 行，每个 lane 负责相邻 4 列。dy 用一条 dwordx4 读、y 用一条 dwordx2 读、结果用一条 dwordx2 写，phase B 的 VMEM 指令减半。行内点积仍按生产版的固定顺序树计算：生产版第 1 级 off=1 求和 p_2j + p_2j+1，正好等于本方案中一个 lane 内的 pa + pb；后面 5 级在 32 组之间按组号的二进制位配对，本方案对应 32 个 lane 的 off = 1..16。浮点加法满足交换律，所以结果逐位一致。
2. **tail 的 phase A 同样改为每条指令处理两行。** 难点是按列顺序做扫描，需要重新分配 wave 和行块。
3. **prep_b：88 条 dword 读。** R scratch 每个 lane 4 B，由 prep_a 写出、prep_b 读入，属于内部交接，可以同时改写读两端的映射。
4. **s4b：**
   - gn 那一行对所有 lane 相同，可以改用标量读（SMEM），每个 wave 少 8 条 TA 指令；
   - k、q 每次只读 32 B 段，可以经 LDS 暂存后合并成宽读；
   - 开头那些转置标量读，P-57 已经测过，收益 0.2–1%。
5. **prep_a：** 受 VALU 限制，主要的 fp 指令都被逐位约束锁定，可改的只剩地址和 mov 两类。

## P-72 结果（bw46，2026-10-15）：逐位一致，但变慢，**不合入**
- **第一版**：dq/dk 约 100 个元素差 1 ulp，原因是 lane 映射改了之后，编译器的打包向量化方式也变了，fma 融合随之不同。生产版 ISA 里，dot 用 `v_pk_mul` + `v_add` 计算（不融合成 fma），输出是 `pk_fma(dy, r, -((dot·y)·r))`。第二版用 `#pragma clang fp contract(off)` 加显式 `__builtin_fmaf`，按这个顺序逐条钉住，逐位门禁 10/10，FI=3 PASS。
  - **新规则 R53**：改 lane 映射时，要把生产版 ISA 的浮点运算顺序（mul/add/fma 的组合）逐条钉住，否则编译器的打包与融合方式变化会破坏逐位一致。
- **A/B**（tail 单 kernel）：

| 形态 | 比值 |
|---|---:|
| 16K/12 | 0.983 |
| 64K/12 | 0.973 |
| 16K/48 | 0.971 |
| 8K/96 | 0.975 |

  VMEM 指令数减半，tail 反而慢了 2–3%。
- **结论（新规则 R54）**：在 gfx936 上，对已经合并良好的行访问，把 dwordx2 换成 dwordx4（总字节不变）不会减少 VMEM 发射受阻；TA 的占用随字节数和访存延迟变化，与指令条数无关（与“TA 在整个取数过程中都被占住”的微基准结论一致）。体检卡里“VMEM 指令倍数”“TA 放大”这两个指标会高估加宽访存的收益。TA 受限的 kernel，能动的只有**字节数**（重复读取、scratch 往返）和 L2 命中率。
- **据此重排候选**（多余字节 = 实测 − 接口必需）：
  - s4b：+239 MB（972 vs 733）；
  - prep_a：+138 MB；
  - prep_b：+127 MB（R scratch 往返，实测 358 MB vs 必需 231 MB）；
  - s4a：+115 MB；
  - tail：+33 MB，已接近字节下限，不再优化。

## 逐张量的多余字节核算（2026-10-15）
- **s4b**：每个 CTA 读约 218 KB、写约 96 KB，乘以 3072 个 CTA 约 965 MB，与 PMC 实测的 972 MB 吻合。多出接口必需量（733 MB）的约 239 MB 主要来自 s4a/s4b 拆成两个 kernel 后的交接：dA 16 KB、dwT 16 KB、db_part 1 KB，加上 h 第二次读入 32 KB，合计每 CTA 65 KB、共约 200 MB；其余约 40 MB 是转置 gather 和 gn 这类广播读中未命中 L2 的部分。
- **s4a**：多出的 115 MB 是写出 dA、dwT、db_part 这份交接数据，每 CTA 33 KB、共约 101 MB。
- **prep_b**：多出的 127 MB 是 R（fp32，每个 chunk·head 20 KB）和 Kb 在 prep_a 与 prep_b 之间的 scratch 往返。
- **结论**：多余字节都是“拆成两个 kernel”带来的交接，属于结构性代价。融合版本以前测过：fused P4''（`KDA_G2_P4=2`）比拆分版慢，R37 也记录过这一点。在 kernel 内部已经没有能单独去掉的多余字节。

## P-73a：s4b 访存模式的上限消融（结果错误，只看时间）
`examples/kda/p73a_s4b_ablate.py`：每轮 kt 中 g、k、q 的读取原本每条指令跨 16 行；消融时改为连续的 1 KB / 512 B，指令数和字节数都不变。在 bw46 上测：

| 变体 | 16K/12 | 16K/48 | 算子 |
|---|---:|---:|---:|
| g、k、q 全改连续 | s4b 1.053（1303→1238 µs） | s4b 1.057（5947→5629 µs） | 1.008 / 1.013 |
| 只改 g | s4b 1.026 | — | 1.005 |

因此，为 s4b 重新安排 g、k、q 的存放方式，最多只能让算子快 0.8–1.3%。真正实现时还要改生产方，或额外写一份 s4b 专用的副本，净收益估计只有 0.3–0.8%。

## 方案 3 小结：逐位约束下，按 chunk 并行的 kernel 已经没有大的杠杆
- **TA 受限的 kernel**（tail、prep_b、s4b、s4a）：TA 占用由字节数和每条指令跨多少行决定（R54）。多余字节来自 kernel 拆分；访存模式的上限约 1%。
- **VALU 受限的 kernel**：
  - prep_a（VALU 82%）：约 18% 的 VALU 是 `expf` 展开（33 组）和 IEEE 除法（42 组）；
  - gate（贴近 VALU 上限）：这两类约占 VALU 的 44%；
  - tail：约 700 条同类指令，但 tail 受 TA 限制。
  如果允许改用原生 `v_exp_f32` / `v_rcp_f32`（结果不再逐位一致，需要用 FP64 oracle 做精度门禁），16K/12 预计可省约 160 µs（约 2.5%）：prep_a 约 −90 µs，gate 约 −70 µs。**这属于 B 类改动，需要用户决定是否放开逐位约束。**
