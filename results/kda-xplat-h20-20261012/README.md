# KDA 算子：BW + hip_kda G2 对比 H20-3e + FLA（2026-10-12）

## 验收口径（用户 2026-10-12 确认）

- **比较对象**：只比算子，不看训练整步。训练整步受 KDA 在一步中的占比影响，暂不考虑。
- **H20 上的对手**：FLA 0.5.2。
- **必须超过的形态**：TP > 1（TP2/TP4/TP8，即每卡 48/24/12 个 head），序列长度 16K/32K/64K，共 9 个形态，这是重点；8K 暂不考虑。

## 方法

- **H20 侧**（`examples/kda/op16_h20.sh`）：与 A800 的 `op16_nv.sh` 相同。每个形态在一张卡上顺序跑 3 个进程的 `kda_op_bench_nv.py`，测 fla（默认）和 fla_nr（disable_recompute）两种配置，指标是 CUPTI 统计的 kernel 时间之和，取中位数。
- **BW 侧**：同一时段用 `round_vs_a800.sh` 测当前生产版，每个形态 5 个进程，并按 R20 加地址抖动；同一会话内还交替测了第 11 轮生产版作为对照。
- **分阶段对比**：H20 用 `nv_kernel_breakdown.py`，BW 用 `bw_kernel_breakdown.py`，再由 `stage_compare_vs.py` 按与 A800 研究相同的功能阶段归类，详见 `stage_compare.md`。

## 结论

1. **FLA 在 H20 上比在 A800 上快 1.37–1.47 倍。** H20 的带宽是 A800 的约 2.2 倍，但 FLA 的提速远小于这个比例，说明 FLA 在 H20 上并非完全受访存带宽限制。
2. **9 个重点形态上，我们是 H20 FLA 默认配置的 0.69–0.83（几何平均 0.76）**，要追平需要提速 1.20–1.44 倍（几何平均约 1.32 倍）。相对 FLA 最快配置是 0.63–0.73。对 A800 FLA 默认配置，这 9 个形态已经全部达到或超过 1.00（1.00–1.20）。
3. **分阶段看**（16K/TP8）：
   - wy + intra（s4a + s4b）我们更快，1.23 倍；
   - 其余阶段都慢：前向准备 0.56，反向重算 0.54，dAv 0.31，dhu 0.65，收尾 0.36，前向递推 0.86。
   - 按带宽差（H20 实测带宽是 BW 的约 2.89 倍）归一化后，除 dAv（0.89）外，我们在每个阶段的字节效率都等于或高于 FLA（1.04–3.55）。
   - **差距的根源是硬件带宽，不是实现效率。** 要赢，只能从结构上减少字节。
4. **显存余量**：每个 token·head 保存给反向的字节数，FLA 默认为 1032 B，我们只有 520 B。一份 bf16 的 chunk 状态 h 正好是 512 B/(token·head)。
   - 前向把 h 存下来，总量 1032 B，与 FLA 默认持平，反向就不必再跑状态递推（`fwd_h_v8o4#2`），v_new 可以由已存的 h 按 chunk 并行算出。
   - `fwd_h_v8o4#2` 占总时间的 6–8%，替换后预计净省 3–5%。这是在不多占显存的前提下能做的结构性改动。
