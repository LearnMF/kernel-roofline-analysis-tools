# KDA 前向 + 反向数据流 IR（第二阶段第 ② 步，2026-10-13）

工具：`examples/kda/kda_ir.py`。所有量都按每 token·head 计，任何形态都是 T×H 乘以同一组数字。

## 1. 结构：三层

| 层 | 内容 |
|---|---|
| 逻辑层 | 算法里的张量（39 个）和运算（18 个），与 kernel 拆分无关。每个运算标注：<br>• 并行结构：按行 / 按 chunk / 正向递推 / 反向递推 / 沿 T 归约；<br>• 递推能否按 V 切分；<br>• MAC 数（三角乘积按一半计）；<br>• 元素级运算和超越函数的数量 |
| 物化层 | 逻辑张量在显存里的一种存法：dtype + 布局（行主序 / A、B、C 形式原生片段 / bN 状态块 / aN / vB）。同一个张量的多种物化就是布局副本 |
| 拆分层 | kernel = 一组运算 + 它从显存读写的物化张量。**生产版（P-54a）是第一个实例** |

此外定义了算法写法的变体（`formulation()`），供第 ④ 步搜索使用：
- **W/U**：显式构造（生产版），或不构造（FROST 式，递推直接使用 k、v、T⁻¹ 和门控）；
- **状态**：反向重算（生产版），或前向保存（keep-state）；
- **dAqk**：由 dav 计算（生产版），或在 s4b 里重算（P-55）；
- **chunk 大小**：32 / 64 / 128。

## 3. 第一批结论

### 3.1 生产版的中间张量流量按原因分解（`breakdown.md`，C=64）

| 原因 | 每 token·head（写 + 读） | 占比 | 说明 |
|---|---:|---:|---|
| crossing | 8464 B | 44% | 按 chunk 并行的运算与递推之间必须交接的张量；由算法写法决定，与拆分无关（下限 8224 B） |
| **handoff** | **8712 B** | **45%** | 按 chunk 并行的反向被拆成多个 kernel 后，kernel 之间的交接：<br>• g（fp32）1536 B；<br>• qn、kn 各 1024 B（各被 3 个 kernel 读）；<br>• dq、dk、dg（fp32）各 1024 B；<br>• dAqk、dA、dwT、kgB 各 512 B |
| copy | 1024 B | 5% | Wb（W 的 B 形式）、dOT（do 的 B 形式） |
| saved | 676 B | 4% | 前向留给反向的 T⁻¹、Aqk、rstd、beta |
| extra_read | 280 B | 1% | 交接张量被同一侧多个 kernel 重复读取（如 Vn 被 dav 和 s4 各读一次） |
| 合计 | 19156 B | | |

**含义**：拆分层的差距里，最大的一块不是递推与并行阶段之间的交接（那部分由算法写法决定），而是**按 chunk 并行的反向内部被拆成 l2n_apply、head_gate、wu、dav、s4a、s4b、tail 后产生的交接，占 45%**。拆成这么多 kernel，根本原因是每 CU 64 KB LDS、每 wave 256 个 VGPR 放不下整个工作集（F6）。如果按 chunk 并行的部分能在容量允许的范围内合并得更好，这部分字节就是可以省的。省下多少字节、又要付出多少指令和延迟代价，要等第 ③ 步的构造式模型来定价（R36：字节不等于时间）。

### 3.2 各种算法写法必须跨阶段交接的字节数（`crossing.md`，写 + 读）

| 写法 | C=32 | C=64 | C=128 | 递推遍数，每步依赖的乘积数 |
|---|---:|---:|---:|---|
| **生产版**：W/U 显式构造、重算 | 10176 | **8224** | 7440 | 3 遍：[4, 2, 3] |
| W/U 显式构造、keep-state | 9664 | 7712 | 6928 | 2 遍：[4, 3] |
| W-free、重算 | 11592 | 9768 | 9240 | 3 遍：[5, 3, 4] |
| W-free、keep-state | 11592 | 9768 | 9240 | 2 遍：[5, 4] |

- **W-free（FROST 式）在 gfx936 上不划算**：
  - 交接字节反而多了约 1.5 KB，因为递推要读 fp32 的 g 来现场计算衰减，还要读 kn、v、T⁻¹；
  - 每个递推每步多一个依赖的乘积，拉长了 TP8 的关键路径。

  这是第一次定量回答“不构造 W 的写法值不值得”。
- **keep-state**：少交接 512 B，少一遍递推；代价是前向要在递推链上多写数据（P-50 标定：每条写指令约 205 周期），并且要多占显存。
- **chunk 大小**：交接字节随 C 增大而减少（状态字节按 1/C 缩放），但 C×C 张量和每步的工作量都会变大。之前的单步微基准不支持 C=128 / C=32，最终要由构件库的递推单步模型来定价。

## 4. 局限
- 布局只是标签（natA / natB / natC / bN / aN / vB / row），每种布局对生产方和消费方的访问代价，要等构件库（`docs/tasks/kda_blocks_task.md`）给出。
- 变长、门控 precomputed、allow_neg_eigval 等分支没有建模。beta sigmoid、to_gn / exp2 这些小运算并入了总量，或者标注为不在 optrace 中。
- 交接字节的计算假设同一侧的消费方已经融合（每次交接按 1 写 1 读计）；实际能融合到什么程度，受容量约束限制，由第 ④ 步决定。

## 5. 下一步
第 ③ 步：构造式成本模型。构件库到手后，按 IR 的运算、物化张量和每个 kernel 的 tiling，组合出时间和 LDS/VGPR 占用。验收标准是**只用构件库“从零”推算现有 11 个 kernel 的时间，误差 ±20–30%**。
