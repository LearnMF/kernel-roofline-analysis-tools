# keep-state 重测（2026-10-13，生产版 7ff2524，bw52）

**测法**：`kda_op_bench_tp.py`，在同一张卡上对比 FLA 默认与 G2，G2 分别跑 `KDA_G2_KEEP_STATE=0` 和 `=1`，每组 9 次取中位数，并重复 2 轮。
- “保存的字节”指前向留给反向的显存，含 o，按每 token·head 计；
- “峰值”指一次前向加反向的峰值显存。

**keep-state=1 做了什么**：前向递推额外写出 h（bN，512 B）、Vn（256 B）和 aN（256 B）；反向因此省掉 fwd_h_bn 这一整遍重算，wu 也不再写 P1 那几份布局。

| 形态 | 保存字节：G2 k0 / k1 / FLA | 峰值 GiB：k0 / k1 / FLA | kernel 前向+反向 ms：k0 → k1 | k1 / k0 | 墙钟 k1 / k0 |
|---|---|---|---|---:|---:|
| 16K/TP8 | 520 / 1544 / 1032 | 1.32 / 1.37 / 1.65 | 6.69 → 6.39 | **0.955** | 0.953 |
| 16K/TP4 | 520 / 1544 / 1032 | 2.64 / 2.73 / 3.29 | 13.02 → 12.75 | 0.979 | 0.976 |
| 16K/TP2 | 520 / 1544 / 1032 | 5.28 / 5.47 / 6.59 | 24.52 → 24.11 | 0.983 | 0.979 |
| 32K/TP8 | 520 / 1544 / 1032 | 2.64 / 2.73 / 3.29 | 12.85 → 12.24 | **0.952** | 0.951 |
| 32K/TP2 | 520 / 1544 / 1032 | 10.56 / 10.93 / 13.18 | 51.49 → 48.40 | **0.940** | 0.938 |
| 64K/TP8 | 520 / 1544 / 1032 | 5.28 / 5.47 / 6.59 | 24.89 → 23.95 | 0.962 | 0.962 |

## 16K/TP8 的 kernel 账目（kt_env）

| 项 | µs |
|---|---:|
| fwd_h_bn（反向重算，被省掉） | −537 |
| wu（不再写 P1 布局） | −21 |
| 前向递推（多写 h、Vn、aN：受延迟限制的递推每步多写 1 KB/token·head，直接拉长关键路径） | +262 |
| dhu | +25 |
| **净** | **−276**（−4.1%） |

## 结论

1. **完整 keep-state 快 1.7–6.0%。** TP8 约 4.5%；TP2 在 16K 时只有 1.7%，32K 时为 6.0%。
2. **显存**：
   - 保存的字节是 1544 B/token·head，比 FLA 默认（1032）多 512 B，即 1.5 倍。
   - 峰值显存仍低于 FLA 默认（例如 16K/TP2：5.47 对 6.59 GiB）。
   - 训练时每层保存的字节会在所有层之间累积，所以按“保存字节”计，这已经超出 FLA 默认的显存预算。
3. **与 FLA 默认显存相等的版本**：只保存 h（512 B），总量正好 1032 B/token·head，与 FLA 默认相同。反向需要按 chunk 并行重算 v_new = U − W·h，wu 也要恢复写 Wn/Un。估算：

   | 形态 | 省掉 fwd_h_bn | 前向只写 h | v_new 重算 kernel | 净收益 |
   |---|---:|---:|---:|---:|
   | TP8 | −537 µs | +130 µs | 约 +200 µs | **约 −3%** |
   | TP2（16K） | −1.63 ms | +0.3 ms | 约 +0.8 ms | **约 −2%** |

4. **Megatron 全层重算下的 auto 模式**：auto 只在重算出来的那一层里保留状态，等这层反向结束就释放，不会在层与层之间累积。端到端的 hip0 对照组按约定用的是 KEEP_STATE=0。

## P-50：只存 h、显存与 FLA 默认相等（`KDA_G2_KEEP_STATE=h`）

**实现**（examples/kda/p50_keep_h.py，树 g2_p50k）：
1. **前向**：递推新增 MODE 5，只输出 Ob 和 HbN，宽版 kernel 也一样。前向只多存 bN(h)。
2. **反向**：跳过 fwd_h_bn。新增 `g2_vnew_h_kernel`，每个 (head, chunk) 一个 CTA，依次处理 4 个 V-slab：先按 bN_emit 的逆映射把 bN 装回 hB，再原样执行 GEMM1 和舍入，得到 Vn = U − W·h。
3. **wu**：恢复写 Wn/Un。Kn 也照写，因为不写反而让 wu 变慢（708 对 646 µs）；Kn 只在反向期间临时占用，不影响保存的显存。

**正确性**：8192:12 和 32768:48 两组与生产版（重算路径）对比，8 个输出全部逐位一致，后者走 64 列宽版 kernel。

**显存**：保存 1032 B/token·head，与 FLA 默认相等；峰值与 k0 相同，低于 FLA。

| 形态 | kernel 前向+反向 ms：k0 → h | h / k0 | 墙钟 h / k0 |
|---|---|---:|---:|
| 16K/TP8 | 6.69 → 6.61 | 0.989 | 0.977 |
| 16K/TP4 | 13.01 → 13.34 | **1.025** | 1.021 |
| 16K/TP2 | 24.50 → 25.84 | **1.055** | 1.051 |
| 32K/TP8 | 12.79 → 12.75 | 0.997 | 0.988 |
| 32K/TP2 | 50.40 → 52.66 | **1.045** | 1.050 |
| 64K/TP8 | 24.63 → 24.94 | 1.012 | 1.010 |

**16K/TP8 账目**：

| 项 | µs |
|---|---:|
| fwd_h_bn（被省掉） | −535 |
| 前向递推多写 bN | +140 |
| v_new 重算 kernel | +339 |
| **净** | **约 −56** |

**v_new kernel 为什么慢**：它的显存流量是 W + U + bN 读，加 Vn 写，约 1.28 KB/token·head，按带宽算下限约 190–230 µs，实测 339 µs。SQTT 显示发射延迟占 51%，等待显存占 35%。改为“一次预取全部四个 slab”反而更慢（400 µs）。

**结论**：用独立 kernel 重算 v_new 时，W/U 要先由 wu 写出、再由新 kernel 读回，正好抵掉省下的 fwd_h_bn。TP8 基本持平，TP4/TP2 慢 2.5–5.5%。**不合入。**

**唯一可能划算的形式**：把 v_new 的计算放进 wu。wu 本来就在寄存器里算出 W（A 形式）和 U（C 形式），只需再按 slab 读 bN 到 LDS、做 GEMM1，写出 Vn，就不必再写 Wn/Un/Kn。按字节估算，反向比重算路径少约 1.5 KB/token·head。估计 TP8 约 −4%，TP2 约 −3%，但要改动 wu 这个最复杂的 kernel。
