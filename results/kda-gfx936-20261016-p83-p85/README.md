## P-83：s4a 把前段各阶段和 pass W 的 global 读取全部提前发出（`examples/kda/p83_s4a_pf.py`，模板参数 PF）

**做法**：
- 先发出两个 beta 读取，然后按使用顺序依次发出：A 块、dvN 片段、v 行、全部 8 个 h 块（每线程 16 B）、全部 8 个 kgB tile（每线程 8 B）。vmcnt 是按发出顺序退役的，所以按使用顺序发就不会互相拖累。
- pass W 完全展开（下标都是静态的，满足 R55），每轮只把下一块写进 LDS 的双缓冲槽。
- 资源：VGPR 由 152 增到 209–233，没有用 scratch，LDS 不变，每 CU 仍放 2 个 CTA。

**结果**：门禁 GATE_ALL PASS，FI=3 PASS。

| 形态 | wy_s4_split（s4a+s4b） | 前向+反向 |
|---|---:|---:|
| 16K/12 | 1913.7 → 1866.8 µs（**1.025**） | **1.009** |
| 64K/12 | 7372.9 → 7145.4（**1.032**） | **1.011** |
| 16K/48 | 8964.6 → 8668.7（**1.034**） | **1.014** |
| 8K/96 | 11849.7 → 11426.3（**1.037**） | **1.012** |

s4a 单 kernel 快了约 8–14%。**合入**。

## P-84：wu 的 VNEW 提前读 bN（`examples/kda/p84_wu_hpf.py`）——**否决**，原因是诊断归错了位置

**结果**：
- wu 单 kernel：1.018（16K/12）、1.020（16K/24）、0.982（32K/48）；
- 前向+反向：1.000–1.004。

**原因**：开启 HPF 后再抓 SQTT（`wu_hpf_16k12.txt`），那处每个 wave 8 次的 `vmcnt(1)` 仍占 14.7%。它根本不在 VNEW 里，而在 phase 1。phase 1 每轮先读 k 和 g，同一轮里又往 global 写 kgB 和 KgA；因为指针没有 `__restrict__`，编译器只能假设这些写可能与下一轮的读重叠，于是不敢把下一轮的读提到本轮的写之前，8 轮的访存延迟就一轮一轮串起来了。

**新规则 R58**：根据 SQTT 等待点设计探针之前，必须先把等待点对应到源代码的具体位置（用 PC/ISA 映射，或 P-76 的 vm_wait_map），不能只凭“每个 wave 出现几次”来猜是哪段代码。

后续：P-84b 在 phase 1 先把 k、g 全部读进 kgr[]/egr[]，再进入计算循环，见下文。
