# KDA 前向 + 反向的第一性原理下限模型（第一版，2026-10-12）

工具：`examples/kda/kda_bound.py`。模型只看算法本身，不依赖任何 kernel 拆分。完整表格见 `bounds_P1.md`、`bounds_P2.md`。

## 模型

| 项 | 怎么算 |
|---|---|
| 访存 | 必须读写的显存字节 ÷ 实测读、写带宽 |
| 矩阵乘 | 算法所需的矩阵乘 FLOPs ÷ 矩阵乘峰值 |
| VALU + 超越函数 | 逐元素运算量 ÷ VALU 吞吐（fp32 有一半可成对执行）+ 超越函数次数 ÷ exp2 吞吐 |
| 递推延迟链 | 串行遍数 × chunk 数 × 每步最小延迟 |

- **下限**：四项完全重叠时取最大值；“区间上沿”是吞吐项中的最大值加上延迟链。
- **显存策略 P1**（与 hip_kda、FLA 默认一致）：前向保存 rstd、Aqk、T；反向多跑一遍递推来重算状态，共 3 遍串行。
- **显存策略 P2**：前向额外保存 bf16 的 chunk 状态 h（每 token·head 多 512 B，总量与 FLA 默认的 1032 B 持平），共 2 遍串行。

**每个 token·head 的工作量**（P1，C=64，d=128）：

| 项 | 数量 |
|---|---:|
| 矩阵乘 | 504 kFLOP（前向 141，反向 281，重算 82） |
| VALU 运算 | 12.5K 次 |
| 超越函数 | 1.5K 次 |
| 显存读 / 写 | 2576 B / 1548 B |

## 第一版结论（P1）

| 形态 | BW 下限（瓶颈项） | H20 下限（瓶颈项） | A800 下限（瓶颈项） | ours / BW 下限 | FLA@H20 / H20 下限 | FLA@A800 / A800 下限 |
|---|---|---|---|---:|---:|---:|
| 16K/TP2 | 2.62 ms（访存） | 2.86 ms（矩阵乘） | 1.83 ms（访存） | 10.1 倍 | 6.4 倍 | 14.4 倍 |
| 16K/TP8 | 0.65 ms（访存） | 0.72 ms（矩阵乘） | 0.46 ms（延迟链*） | 10.3 倍 | 7.2 倍 | 16.2 倍 |
| 64K/TP8 | 2.62 ms（访存） | 2.86 ms（矩阵乘） | 1.84 ms（延迟链*） | 9.3 倍 | 7.1 倍 | 15.9 倍 |

\* NV 机器的每步延迟暂按 0.6 µs 估计，尚未测量。

1. **三个实现离各自的下限都有 6–16 倍**：照搬 FLA 的拆分方式，无论在哪台机器上都远离极限。
2. **原理上 BW 能赢 H20**：H20 矩阵乘只有 138 TF，到极限时受矩阵乘限制，下限比 BW 高约 10%。
3. **A800 的下限比 BW 低约 1.4 倍**：两者到极限都受访存限制，A800 带宽更高。要赢 A800，只能靠我们的实现比 FLA@A800 更接近各自的下限。目前我们是 10 倍，它是 14–16 倍，所以现在我们在部分形态上领先。

## 差距拆解（16K/TP8 和 16K/TP2，按 kra 采到的每个 kernel 计数器）

| 资源 | 实际执行（每 token·head） | 算法必需 | 多出 |
|---|---:|---:|---:|
| 显存字节 | 25.8–26.7 KB | 4.1 KB | **6.3–6.5 倍** |
| VALU 运算 | 84–85K 次（可能含矩阵乘指令，见待验证 4） | 12.5K + 1.5K 次超越函数 | **约 6 倍** |
| 矩阵乘 | 503 GFLOP（16K/12） | 108 GFLOP | **4.7 倍** |

**以 16K/TP8 为例，从下限到实测的逐层分解**：

| 层 | 时间 | 倍数 | 原因 |
|---|---:|---:|---|
| 下限 | 0.65 ms | | 访存 |
| 现有字节按 100% 带宽搬运 | 3.9 ms | ×6.0 | 多余的字节：中间张量、布局副本、重复读取，来自拆分方式 |
| 实测 | 6.8 ms | ×1.74 | 执行效率：平均只用到峰值带宽的约 57%（受发射、延迟、递推的并行度限制） |

**VALU 也是一个必须控制的量**：现在执行的 VALU 按 BW 的吞吐需要约 2.15 ms（16K/TP8），已经是访存下限的 3 倍。新设计只消掉多余的字节还不够：VALU 不同时降 3–4 倍，就会成为新的瓶颈（约 2 ms）。多出来的 VALU 主要来自：门控和衰减 exp 在多个 kernel 里重复计算、布局转换和转置、64 位地址运算、Kahan 补偿求和，以及累加器清零等。

## 待验证（模型本身有没有漏项）

1. **VALU 和超越函数的算法量目前是粗估**：safe gate 子块参考点需要的额外 exp、反向链式求导的逐元素量，都要逐项精确计数。
2. **BW 的递推每步延迟**：解析估计 0.40 µs，需要写一个最小状态更新的微基准来测；NV 机器取 0.6 µs，也只是估计值。
3. **小分块、带掩码时矩阵乘实际能达到的峰值比例**。
4. **valu_insts 是否把矩阵乘指令也算进去**：如果算进去，每个 token·head 约 20K 次，扣除后 VALU 多出的倍数约 4.6 倍。
