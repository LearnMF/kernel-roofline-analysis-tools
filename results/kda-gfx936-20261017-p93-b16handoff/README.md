# P-93：放开约束的选项 B1 —— s4b 交给 tail 的数据改用 bf16（2026-10-17，bw46，只评估，不合入，结果不再逐位一致）

**脚本**：`examples/kda/p93_b16_handoff.py`。
- 默认：dq、dk、dg 三个都用 bf16。
- `--qk-only`：只有 dq、dk 用 bf16，dg 仍是 fp32。

s4b 把 fp32 结果做一次 RNE 舍入后写出，tail 读回后再转成 fp32 计算，其余计算和累加全部保持 fp32。

## 精度
用 `tests/g2/fp32_ref_check.py`，即项目原有的 S2 判据：每个输出相对 fp32 参考的相对 L2 误差，不得超过 FLA 误差的 1.10 倍。

|---|---|---:|---:|---:|---:|
| 4K/12 | dq | 0.00459 | 0.00457 | 0.00486（FLA 的 1.06 倍） | 0.00486 |
| | dk | 0.00519 | 0.00517 | 0.00543（1.05 倍） | 0.00543 |
| | dg | 0.00617 | 0.00543 | 0.00543（与生产版相同） | **0.01031（1.67 倍）** |

| 4K/48 | dg / dA_log / ddt_bias | 0.00611 / 0.00415 / 0.00646 | 0.00543 / 0.00396 / 0.00548 | 与生产版相同 | 0.01024 / 0.00718 / 0.01615 |
| S2 判据 | | — | PASS | **PASS（3 个形态）** | **FAIL（3 个形态）** |

dg 不能用 bf16：tail 要对 dg 做反向累加（cumsum），再归约到 dA_log 和 dt_bias，每个元素的舍入误差会一路累积。dq、dk 改成 bf16 只多出约 5–6% 的误差，仍在 FLA 的 1.10 倍以内。

## 速度
ab_kernels，同一张卡上交替各跑 5 轮。两组跑在不同的卡上（HCU3、HCU4），这两张卡的绝对时间相差约 8%，所以只比较各自的比值。

| 形态 | B1′：s4b | B1′：tail | **B1′：合计** | B1：s4b | B1：tail | B1：合计 |
|---|---:|---:|---:|---:|---:|---:|
| 16K/12 | 1.052 | 1.154 | **1.026（−141 µs）** | 1.082 | 1.312 | 1.052 |
| 16K/48 | 1.065 | 1.180 | **1.032（−723 µs）** | 1.121 | 1.306 | 1.047 |

## 结论
- **B1′ 是可行的放开选项**：结果不再逐位一致，但满足项目原有的“不差于 FLA”精度判据，TP8 快 2.6%，TP2 快 3.2%。按此估算，对 H20 的比值在 16K/TP8 从 0.92 升到约 0.94，在 16K/TP2 从 0.84 升到约 0.87。
- **B1（dg 也用 bf16）不可行**：dg、ddt_bias、dA_log 的误差是 FLA 的 1.6–2.6 倍。
- **B2（g 改用 bf16）没有实现**，从原理上就不可行：g 是块内累加的对数门控，量级可达 |lower_bound| × 64 ≈ 320。在这个量级上 bf16 的步长是 1–2，exp2 之后相对误差会达到 100% 的量级。
- 要不要采用 B1′，需要用户决定：这是从“逐位一致”退到“不差于 FLA”。
