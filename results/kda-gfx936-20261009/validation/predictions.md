## P-1 wu：LDS bank conflict（登记于 2026-10-09）

**工具结论**（`waterlevel/g2_8192_12`）：
- 实测 477.3 µs；HBM SOL 62%，`B.memory.hbm`，结论 throughput_bound；
- 先验下限 254 µs，实现下限 296 µs；
- D 层病因：`D.lds_conflict = 19.6%`，即 `SQ_LDS_BANK_CONFLICT / (周期 × CU)`。

**机制分析**：用 `kra/lds/bankmodel.py` 和 `examples/kda/wu_lds_model.py` 建模，基线预测每个 wave 1568 个冲突周期；计数器实测为每个 wave 1824 个，模型解释了 86%。冲突来源有四处：
- phase-1 / phase-2 fill 的 b16 写：8 路冲突，列是 j，行步长 68 short，每行只错开 2 个 bank；
- MMAC 阶段读 sA：8 路冲突，行步长 128 B，所有行落在同一组 bank；
- phase-3 tile 的 b16 写：8 路冲突。

**修改**：只改 LDS 布局，不改任何数值计算，因此预期逐位一致。
- slab 的列按 8 B 粒度 XOR `(row >> 3) & 15`；
- sA 每行填充到 68 short；
- tile 的 8 B 粒度 XOR `(e >> 10) & 7`；
- 读写两侧使用同一映射。

LDS 用量从 26,368 B 增加到 26,880 B，每个 CU 仍然放 2 个 CTA。

**模型预测**：每个 wave 的冲突周期 1568 → 192（减少 88%），LDS 总周期 2096 → 720。

**预测**（8K/H12；8K/H48 方向相同）：

| 指标 | 基线 | 预测 |
|---|---:|---:|
| `D.lds_conflict` | 19.6% | **≤ 4%** |
| wu kernel 时间 | 477 µs | **400–460 µs**（快 4–16%）。冲突周期占 CU 周期的 19%，部分会被其他 wave 的访存等待掩盖，所以不会全部变成收益 |
| HBM SOL | 62% | 65–75% |
| 先验下限 | 254 µs | 不变（下限与实现无关） |
| 实现下限 | 296 µs | 不变或略降，实测不会低于它 |
| 算子 fwd+bwd 总时间 | 4.47 ms | 快 0.4–1.7% |

**证伪条件**：
- 冲突占比下降，但时间变化落在噪声内 → “冲突在关键路径上”的判断错误，说明 wu 主要受访存延迟限制；
- 冲突占比没有降到预测水平 → bank 模型不成立。

## P-2 prep_a：VALU 吞吐（登记于 2026-10-09，P-1 结果出来之后、修改之前）

**工具结论**：
- prep_a 为 `B.compute.valu`，流水线利用率 76.2%，实现达成率 74%，属于吞吐受限；
- L3 显示整数与选择类指令占发射延迟的 41%（`D.addr_overhead`）；
- SQTT 指令计数：`v_cndmask` 占 17.4%，`v_cmp_gt_f32` 占 8.2%，`v_exp_f32` 只占 3.9%。

**机制**：ISA 显示每个 `exp2f` 被展开成 6 条指令（`v_cmp_gt` → `v_cndmask` → `v_add` → `v_exp` → `v_cndmask` → `v_mul`），用来处理结果小于 2^-126 的非规格化情况。参数 x ≥ -126 时，这串指令严格等价于单条 `v_exp_f32(x)`：加 0、乘 1.0 都是精确运算。

**修改**：只改参数在安全门控契约下可证明落在 [-126, 128) 内的调用点，换成硬件 exp2。契约是每个 token 的衰减 ≥ -5 nat，即 ≥ -7.2135 log2 单位：
- P1a 的 `eA`、`eB`：离参考行最多 8 行，|参数| ≤ 57.7；
- P1b 的 `eO`：最多 15 行，|参数| ≤ 108.2。

每个线程共 88 个调用点。其余调用点（QgA/Kb 的 `exp2f(G)`、T2 的 `exp2f(gn-G)`、P1b 的 `eBo`）参数可能低于 -126，保持不变。

**预期逐位一致**：在 [-126, 128) 范围内结果相同；超出范围的调用点没有改。

**预测**（8K/H12）：

| 指标 | 基线 | 预测 |
|---|---:|---:|
| 每个 wave 的 VALU 指令 | 5438 | 约 4998（少 440 条，8.1%） |
| VALU 发射槽 | 6844 | 约 6404（少 6.4%） |
| prep_a 设备时间 | 460 µs | **430–447 µs**（快 3–6.4%）。kernel 受流水线吞吐限制，时间大致随发射槽数缩放；但利用率只有 76%，不是 100%，所以按 0.5–1.0 倍折算 |
| 类别 | B.compute.valu | 不变，利用率持平或略降 |
| 其他 kernel | — | 不变 |

**证伪条件**：
- 指令数按预期减少，但时间变化在噪声内 → “VALU 吞吐受限”的判断有误；
- 逐位一致失败 → 参数范围的推导有误。

## P-3 s4a：剂量-响应试验，检验 L3 判断“全局读发射在关键路径上”（登记于 2026-10-09，修改之前）

**工具结论**：
- s4a 属于 C 类（延迟受限）；
- L3 显示 `C.vmem_issue` 36%（卡在 `global_load` 发射的占 30%，其中 `global_load_dwordx2` 一项 26.8%），`C.wait_exposed` 35%；
- 静态 ISA：每个 lane 约 180 次 8 B 全局读。其中 h（64 次）、vBN（32 次）、kgB（32 次）的地址只取决于 lane，同一个 CTA 的 4 个 wave 读的是完全相同的数据；
- VGPR 183，每个 CU 放 2 个 CTA，受寄存器限制。

**改动（试探剂量）**：pass W 里的 `af[vt] = aN(dvN, vt)` 重新读取了 `dva[vt]` 已经在寄存器里的同一组数据（中间隔着 `lds_barrier` 的 memory clobber，编译器不能合并）。改为直接使用 `dva`。每个 lane 少 8 次全局读，约占全部 8 B 读的 4.4%。数值完全不变。

**预测**（8K/H12）：

| 情形 | s4a 设备时间（基线 399.5 µs） |
|---|---|
| 如果读发射确实在关键路径上（工具的判断） | **快 1–4%**，按 30% 的读发射停顿占比乘以 4.4% 的剂量，再留出非线性余量 |
| 如果不在关键路径上 | ±0.3% 以内 |

**用途**：结果为正，就做 P-4（把 h/vBN/kgB 经 LDS 每个 CTA 只读一次，可省约 53% 的全局读）；结果为零，就说明 s4a 的 C 类子类型判断有误，P-4 不做。

**风险**：`dva` 的生命周期延长可能增加 VGPR。如果 VGPR 超过 184，占用率会从 2 个 CTA 掉到 1 个，这种情况下实验无效，记为“剂量不纯”。

## P-4 s4a：h 操作数每个 CTA 只读一次（登记于 2026-10-09，P-3 结果出来之后、修改之前）

**依据**：P-3 的剂量-响应。少 4.4% 的读，s4a 快 3.0%（398.6 → 386.9 µs），换算比例约 0.68，说明读发射确实在关键路径上。

**改动**：
- pass W 中的 h 分块（每个 kt 是 8 个 vt × 512 B = 4 KB）原来由 4 个 wave 各自用 8 次 8 B 读取一遍；
- 改为 256 个线程各用 1 次 16 B 读（`dwordx4`）协作读入 XT。XT 在 pass W 期间空闲，8704 B 足够放 2 × 4 KB 双缓冲；
- 每个 wave 再用 `ds_read_b64` 从 LDS 取自己的片段，片段布局与全局内存相同，没有 bank 冲突；
- 每个 kt 结束时加一个 barrier，共 8 个；下一个分块的全局读在 barrier 之前发出，预取距离为 1 个迭代；
- 数值完全不变。

**剂量**：每个 lane 的 h 读从 64 次 8 B 降到 8 次 16 B。全局读指令约少 56 条，占 s4a 动态读指令的 31%。新增 64 次 LDS 读、8 个 barrier。

**预测**（8K/H12，基线是 P-3 之后的 386.9 µs）：

| 指标 | 预测 |
|---|---|
| 逐位一致 | 一致 |
| VGPR / LDS | VGPR ≤ 184，LDS 不变（26112 B），每个 CU 仍放 2 个 CTA |
| s4a 设备时间 | **300–360 µs（快 7–22%）**。上限按 P-3 的比例 0.68 线性外推，并受读发射停顿占比（30%）封顶；下限扣除新增 barrier 和 LDS 读的开销 |
| 8K/H48 | 方向相同 |

**证伪条件**：时间变化 < 3%，说明剂量-响应不能外推；或者变慢，说明 barrier 引入了同步开销（会表现为 L3 的 C.sync）。

## P-5 s4b：序言里串行暴露的标量 gather（登记于 2026-10-09，修改之前）

**工具结论**：
- s4b 为 C 类；L3 显示 `C.wait_exposed` 47%，气泡中 `exec_branch→waitcnt` 占 8–10%；
- 新增的静态加载-使用距离分析（`kra/isa/scan.py::load_use_slack`）找到 12 个“`global_load_dword` 之后 5–6 条指令就 `s_waitcnt vmcnt(0/1)`”的等待点。

**来源**：`s4b_tail` 序言里的 `akB/aqB[b-A][x] = keep ? dAg[j*RA+row] : 0`。`keep` 取决于 lane，编译器把每一对读放进一个发散分支，并在分支合并前等待它完成，于是读取被串行化。A=0 的 wave 要做 4×4 对，也就是 16 次串行的访存往返。

**改动**：
- 地址总是合法时（dA 交接缓冲按 chunk 补齐），无条件发出读，读回后再按 `keep` 选择；
- `aq_` 在变长尾块时，把行号夹到 0（这一行一定存在）再读，然后按原条件选 0；
- 选出来的值与原来完全相同。

**预测**（8K/H12，基线 714 µs）：

| 指标 | 预测 |
|---|---|
| 逐位一致 | 一致 |
| VGPR / scratch | VGPR ≤ 256，不溢出（`private_segment_fixed_size` = 0）。如果溢出，实验作废 |
| s4b 设备时间 | **670–705 µs（快 1.3–6%）**。A=0 的 wave 约有 16 × 约 500 周期 ≈ 8k 周期的串行等待，每个 CTA 约 111k 周期；kt 循环里的 barrier 让最慢的 wave 决定整体时间，部分等待会和其他 wave 重叠 |
| 静态分析 | 序言中 slack < 10 的等待点从 12 个降到 ≤ 2 个 |

**证伪条件**：时间变化 < 1%，说明序言的串行等待并不在关键路径上。

## P-6 dav：pass 2 中发散的 2 B gather（登记于 2026-10-09，修改之前）

**工具结论**：
- dav 为 `C.unresolved`，HBM 46%，先验达成率 43%，可回收 160 µs；
- `load_use_slack` 找到 11 个“`global_load_ushort` 之后 2–5 条指令就 `vmcnt(0)`”的等待点。

**来源**：pass 2 的 `af[e] = (t >= tp && row_ok) ? A[t][tp] : 0`。条件取决于 lane（因果掩码），每次 2 B gather 都在发散分支里等待自己完成，每个 lane 有 16 次串行往返。

**改动**：
- 无条件地读取，A 的行在变长尾块时夹到第 0 行，保证在界内；读回后按原条件选 0；
- 给 js 循环加上 `#pragma unroll`，让 16 次读可以一起发出；
- 数值不变。

**资源**：VGPR 76 → 预计不超过 96；LDS 不变（17.4 KB），每个 CU 放 3 个 CTA，受 LDS 限制。

**预测**（8K/H12，基线约 283 µs）：

| 指标 | 预测 |
|---|---|
| 逐位一致 | 一致 |
| 静态分析 | slack < 10 的等待点从 11 个降到 ≤ 2 个 |
| dav 设备时间 | **快 0.5–4%**。A 的数据大概率命中 L1，每次约 150 周期；每个 wave 16 次 × 约 150 周期 ≈ 2.4k 周期，每个 CTA 约 66k 周期，3 个 CTA 之间还能重叠一部分 |

**证伪条件**：变化 < 0.5%；或者变慢（例如寄存器增加导致占用率下降）。

**修订（P-5 结果出来后、P-6 运行前追加；上面的原始预测保留）**：P-5 消除了同一类暴露点，s4b 的 ISA 也确实变了，但没有收益：每个 CTA 只执行一次的暴露，会被同一 CU 上另一个 CTA 的执行掩盖。dav 的这 16 次 gather 同样每个 CTA 只执行一次，而且 dav 每个 CU 放 3 个 CTA，掩盖能力更强。**修订后的预测：变化 < 0.5%**。用这个实验检验“一次性暴露不在关键路径上”这条新规则是否成立。

## P-7 v8o4：下一步 W 的读取推迟发出（登记于 2026-10-09，修改之前）

**新证据（PC 级归因，`kra/sqtt/pcmap.py`）**：
- 数据来自 XCompute CLI 的 `pipeline` 段，单个 wave 的完整发射流；用 `-gline-tables-only` 编译出的 ISA 做源码映射，已核对 codegen 与生产版完全相同；
- 对齐了 9 个递推步，84% 的停顿被归到具体指令上；每步 5716 周期；
- 停顿最大的一条指令是 GEMM1 之后紧接着的 `loadW(nxt)`（`g2_fwd_v8.cuh:276` 的第一个 `global_load_dwordx2`），每步 **410 周期（7.2%）**，W 的其他读加起来约 150 周期。

**假设 H1**：这次读要写入 `wf` 寄存器，而刚刚发出的 GEMM1 MMAC 还在读这些寄存器（写后读冲突），所以读必须等 MMAC 读完源操作数才能发出。
**对立假设 H2**：停顿来自 TA/VMEM 队列的结构性限制。如果是这样，把读挪到别处，停顿也会跟着搬过去，总时间不变。

**改动**：只调整发射位置。把 `loadW(nxt)` 从 GEMM1 之后挪到 oh MMAC 之后、bar2 之前。挪过去以后，`wf` 早已不再被读取，读取的延迟仍能在下一步之前被掩盖。寄存器数量不变，取数和使用顺序不变，结果逐位一致。

**与历史实验的区别**：GLM 的 Z1（QgA/AqkA 提前一步，中性）和 R3（QgA/AqkA 移到 bar1 之后，在 H=12 快 1.08 倍）挪的都是 Qg/Aq 的读，W 的读位置从来没有动过。

**预测**（8K/H12；fwd_h_o 约 440 µs，fwd_h_bn 约 415 µs）：

| 情形 | v8o4 两次调用合计 |
|---|---|
| H1 成立 | **快 3–9%**：消除 410–560 周期/步中的大部分；读挪到 bar2 之前后，还能填进原来 268 周期/步的屏障等待 |
| H2 成立 | 在 ±0.5% 内 |

**副作用检查**：VGPR、LDS 不变；逐位一致（9 组 dense + 4 组 varlen）。

## P-8 L16：递推操作数改用 16 B 成对布局（登记于 2026-10-10，原型已测、完整实现测量之前）

**依据**：
- 逐指令分析：v8o4 和 dhu 每一步约有 30–40% 的时间耗在全局读的发射上；
- L0 原语 `vmem_issue`：`dwordx2` 每条 16 周期，`dwordx4` 每条 18–23 周期，字节数相同时，16 B 读的发射时间更短。

**改动**：Wn、Wb、Un、Kn、KgA、Qn、QgA、AqkA 这 8 个原生张量改为成对布局：在每 512 个元素的组内，相邻两个 256 元素子块按 lane 交织，一个 lane 用一次 16 B 读拿到两个片段。
- 所有生产者（prep_a、prep_b、wu、fwd_intra、fwd_intra2）的存储都经过 `nat16()`；
- 消费者（v8o4、v8o、v7、dhu v8b4/v8b/w8b）改用 16 B 成对读；
- Python 侧的布局代码（`g2_native.to_*`，以及 convert/convert2 中涉及这些张量的模式）做相同的置换；
- 数值完全不变。

**原型已经测过（`examples/kda/layout16_bench.hip`，随机数据，只看时间，每侧 6 个进程）**：

| kernel | 8K/H12 | 8K/H48 |
|---|---:|---:|
| dhu | 1.187 倍 | 1.131 倍 |
| v8o4 前向 | 1.143 倍 | 1.220 倍 |
| v8o4 反向重算 | 1.105 倍 | 1.084 倍 |

所以这里检验的预测是：**完整实现能复现原型的收益，而且生产者那一侧没有可感知的代价**。

| 指标 | 预测 |
|---|---|
| 逐位一致 | 一致：13 组 dense/varlen 配置，加上树内各组件门禁（它们比较的是原生张量，生产者和消费者必须使用一致的布局） |
| ISA | 与原型相同：v8o4 的 `dwordx2` 从 48 条降到 0，`dwordx4` 28 条；VGPR 175 → 170；没有 scratch |
| v8o4 两次调用 + dhu（8K/H12） | 共节省 **150–200 µs**，各自倍数在原型值的 ±3% 以内 |
| 生产者 kernel（prep_a、prep_b、wu） | 变化在 ±1% 以内：写入仍是 8 B，只是地址变了，L2 会合并写入 |
| 算子总时间 | 8K/H12 快 **1.035–1.045 倍**；8K/H48 快 1.025–1.035 倍 |

**证伪条件**：收益不到原型的一半，或生产者变慢超过 2%。

## P-9 v8o4：可选输出改为编译期确定（登记于 2026-10-10，修改之前）

**证据**（L16 之后重新做逐指令分析；采集用的 `rec_sqtt.hip` 与生产调用的参数组合完全一致；看的是关键 wave）：

| 变体 | 每步周期 | 最大停顿 |
|---|---:|---|
| v8o4 前向（只输出 o） | 4663 | GEMM1 中一条 `s_waitcnt vmcnt(9)`，**730 周期，占 15.7%** |
| v8o4 前向 keep-state | 6232 | 4 条 vmcnt 等待，合计 1270 周期（20%） |
| v8o4 反向重算 | 4848 | exp2f 衰减前的 `vmcnt(12)`，804 周期（16.6%） |

**机制**：
- hot loop 里有 61 个向量访存操作位于运行时可选的分支里（`if (p.O || p.Ob)` 里的 Qg/Aq 读，`p.HbN`/`p.Vn`/`p.ANv` 的写），新的静态规则 `D.waitcnt_conservative` 可以识别出来；

- 例如 GEMM1 前为 W 发出的 `vmcnt(7..10)`，就是按跳过路径数出来的。实际执行这些分支时，它会顺带强迫之后才发出的 K/Qg/Aq 读也必须先返回，而 GEMM1 并不需要这些数据。

**改动**：v8o4 加一个模板参数 MODE，对应生产中的三种组合：前向（只写 Ob）、前向 keep-state（Ob + HbN + Vn + ANv）、反向重算（HbN + Vn + ANv，不算 o）。其余组合继续走原来的通用实例（运行时判断）。launcher 按指针是否为空来选择实例。数学部分逐字不变。

**预测**（8K/H12，基线为 L16 生产版：fwd_h_o 约 380 µs，fwd_h_bn 约 374 µs）：

| 指标 | 预测 |
|---|---|
| 逐位一致 | 一致 |
| 静态分析 | 专门化实例的 hot loop 中，条件分支里的访存操作数为 0 |
| 动态（逐指令） | 前向 GEMM1 那条等待从 730 降到 < 150 周期/步 |
| v8o4 前向 / 反向重算 | 各快 **6–14%**（取那条主要等待的 40–90%） |
| keep-state 前向 | 快 5–15% |
| 资源 | VGPR ≤ 175，不溢出 |

**证伪条件**：时间变化 < 2%，或者那条等待仍在（说明原因另有所在）。

## P-12 L16 剩余的生产者代价：两处 8 B 存储合成 16 B（登记于 2026-10-10，修改之前）

**预测**：

| 其他 kernel | 不变 |

## P-13 反向融合第 1 步：去掉 l2n_apply，由消费者重算（登记于 2026-10-10，修改之前）

**依据**：
- `bwd_fusion_eval.md` 中的方案 A；
- l2n_apply 的计算是逐元素的 `bf_rne(bf2f(x) × rstd[token·H + head])`（`g2_wy.cuh:1303`）；

**改动**：
- 这四个消费者改为读原始 q/k，加上 forward 已保存的 q_rstd/k_rstd，在读入后用与 l2n_apply 完全相同的表达式重算；

**预测**：

| 指标 | 预测 |
|---|---|

| 消费者的额外开销 | wu、tail、s4b 各增加 ≤ 1%（每个元素多一次乘法和舍入；它们都不受 VALU 限制，s4b 的 VALU 利用率是 35%） |
| 算子总时间 | **快 1.4–1.9%**（8K/H12 和 8K/H48，普通形态和 keep-state 都是） |

## P-14：dav 的访存指令减到原来的约 60%（全局路线第 1 轮，2026-10-10，bw52）

**为什么先做它**（全局方向检查，见 `results/kda-xplat-a800-20261010/round1_direction.md`）：
- 在同一块 BW 硬件上，FLA 的 dAv 比我们的 dav 快 2.0–2.25 倍：8K/12 是 139 对 283 µs，8K/96 是 1062 对 2391 µs。也就是说，这个差距**已经有人在同一块硬件上做到了**；
- 这一级在任何拆法里都要保留（dA、dv 是必需的输出），改进不会被后续的结构改动作废；
- 它不在递推链上，风险低，16 个形态都能受益。

**机制**：
- dav 的访存发射占用率是 88%，受访存指令数限制；
- 每个 CTA 实际只搬运约 104 KB 数据，按 16 字节访存算，每个 lane 只需要约 26 条访存指令，但现在每个 lane 发 104 条；
- 其中 dOT 是 32 条零散的 2 字节写，dA 是 16 条标量 fp32 写；
- 按规则 R10（写入一条指令的成本正比于它覆盖的地址范围），这些分散的小写入代价最高。

**改动**（只改访存方式，不改任何数值）：
- dOT：在 pass 2 的转置暂存（slab 是 [v][j] 布局）之后，从 LDS 读两次 8 字节，拼成一次 16 字节的全局写。每个 lane 的写从 32 条降到 4 条；
- dA：pass 1 的 C 片段先写进 LDS（复用 slab，64×68 个 fp32，正好放得下），然后整行用 16 字节写出。每个 lane 的写从 16 条降到 4 条，多 2 次 barrier；
- 每个 lane 的访存指令合计从 104 条降到 64 条。

**预测**：

| 指标 | 预测 |
|---|---|
| 逐位一致 | 13 组全部一致（数值完全不动） |
| dav kernel | 快 25–40%（8K/12 从 283 降到 170–210 µs，8K/96 从 2391 降到 1450–1800 µs） |
| 算子总时间 | 快 1.7–2.5%，16 个形态都受益 |
| 资源 | LDS 不增加（复用 slab），VGPR 不溢出 |

**证伪条件**：dav 快不到 15%，或算子快不到 1%，或任意一个形态变慢超过噪声。

## P-15：wu 去掉 sA 缓存，占用率从每 CU 2 个 CTA 提到 3 个（跨平台第 2 轮，反向重算一级）

**全局方向**：
- 反向重算一级是同一块硬件上最大的缺口：8K/96 时 ours 7.5 ms，FLA@BW 5.2 ms；
- 其中 wu 一个 kernel 就是 4.6 ms，FLA 的 w_u 在 BW 上是 2.36 ms；
- 这一步不改拆法，也不改布局。如果以后减少 wu 的布局副本，这一步的收益依然有效，不会被作废。

**机制**：
- 8K/48 的水位分析显示，wu 的 HBM 只用到 63%，访存发射 38%，流水线 47%，没有一项跑满，属于延迟和占用率受限；
- wu 用 104 个 VGPR，按寄存器每个 SIMD 能放 4 个 wave。但 LDS 用了 26,880 B（slab 17.4 KB + sA 8.7 KB），所以每个 CU 只能放 2 个 CTA，即 8 个 wave；
- 单个 CTA 内是“读入 → MMAC → 写出”串行的几段，靠多个 CTA 互相掩盖。
- sA 只用来提供两个 MMAC 阶段的 A 片段（每个 lane 每阶段 4 次 8 字节读），A 矩阵每个 CTA 8 KB，在 L2 里，直接从全局读即可。

**改动**：
- 删掉 sA 及其填充，A 片段改为从全局按行读，变长时无效行置 0，与原来 sA 填充的规则相同；
- LDS 降到 18,176 B，每个 CU 可以放 3 个 CTA，即 12 个 wave。

**预测**：

| 指标 | 预测 |
|---|---|
| 逐位一致 | 全部一致（A 片段的值相同） |
| wu | 快 10–20%（8K/12 从 475 降到 380–430 µs，8K/96 从 4611 降到 3700–4150 µs） |
| 算子总时间 | 快 1.2–2.6% |
| 资源 | VGPR ≤ 104，没有溢出，LDS ≤ 18.2 KB |

**证伪条件**：wu 快不到 5%，或任意形态变慢。

## P-16：wu 的 kgB/vB 改为经 LDS tile 的 16 字节线性写（跨平台第 2 轮）

**全局方向**：
- 反向重算是同一块硬件上最大的缺口；wu 的时间主要花在分散写上（见 results.md 中 P-16 的依据）；
- 这一步不改拆法，也不改布局，以后减少布局副本时这个改进依然有效。

**改动**：
- 默认路径（Kn 不为空）下，kgB = bf_rne(bf2f(k)·exp2f(g)) 移到 phase 3 计算。phase 3 本来就读 k 和 g，表达式与 phase 1 逐字相同；
- vB（原始 v）在 phase 3 重读一遍 v，v 在 L2 里；
- 两者都按 vB 布局的 quad 位置写进 tile（每个 lane 8 次 8 字节 LDS 写），再线性发射，每个 lane 4 次 16 字节写；
- phase 1 和 phase 2 里原来的 16 条分散的 8 字节写只在 keep-state 路径（Kn 为空）保留，该路径的代码不变。

**预测**：

| 指标 | 预测 |
|---|---|
| 逐位一致 | 全部一致 |
| wu | 8K/96 快 18–25%（4.6 降到 3.5–3.8 ms），8K/12 快 6–9% |
| 算子总时间 | 8K/96 快 2.5–3.5%，8K/12 快 0.6–1.2% |
| 资源 | LDS 不变（26,880 B），VGPR ≤ 256，没有溢出 |

**证伪条件**：8K/96 的 wu 快不到 10%，或任意形态变慢。

## P-17：vB 副本取消，改由 s4a 在片上转换（跨平台第 3 轮，结构改动）

**全局方向**（R15）：
- 处理的是同一块硬件上最大的缺口：反向重算一级；
- 第 2 轮已经证明，在 wu 内部只调访存方式只能拿到边际收益；
- 这一步取消了一份布局副本，把布局转换移到不在递推链上的消费者里，与 FLA 的做法一致。FLA 的 wy_dqkg 直接读行主序的 v；
- 以后用同样的方式取消其它副本，这一步也不会被作废。

**定价**（R12）：
- **vB**：s4a 为了计算 db，本来就按行主序读同一份 v（`v_row`，每个 lane 8 次 8 字节读）。把这些值暂存进 S（此时 dvT 刚用完，空着；64×136 个 short 正好放满 S，LDS 不增加），dA 那次 MMAC 的 B 片段就改从 S 读：
  - 全局访存：每个 lane 少 32 次 8 字节读（每个 CTA 少读 16 KB）；
  - 新增：8 次 LDS 写、32 次 LDS 读、1 次 barrier；
  - 离线 bank 模型：读写都是理想的 4 路；
- **kgB 不动**：在 s4a 里重建 k·2^g 要多读 k 和 fp32 的 g，8K/96 时多 400 MB，与省下的差不多。

**改动**：
- s4a：`v_vb == nullptr` 时走 LDS 路径；这个判断是 CTA 内一致的分支；
- wu：`vB == nullptr` 时跳过 phase 2 那次分散的 vB 写；
- 绑定层与 Python：生产路径（S4=1、P4=3）上 wu 不再输出 vB，s4a 收到空的 v_vb。其它路径（P4≠3、S4=0）保持不变。

**预测**：

| 指标 | 预测 |
|---|---|
| 逐位一致 | 全部一致（B 片段的值和 MMAC 顺序都不变） |
| wu | 8K/96 快 15–22%（4.55 降到 3.6–3.9 ms），8K/12 快 4–9% |
| s4a | 在 −3% 到 +5% 之间（少了 VMEM 读，多了 LDS 读写和一次 barrier） |
| 算子总时间 | 8K/96 快 2.0–3.0%，8K/12 快 0.5–1.0% |
| 资源 | s4a 的 LDS 不变（26,112 B），VGPR ≤ 200，没有溢出 |
| 显存 | 反向少一个 vB 张量（[T,H,128] bf16） |

**证伪条件**：8K/96 的算子快不到 1%，或任意形态变慢。

## P-19：wu 的 phase 3 不再重读 k 和 g（第 3 轮，叠加在 P-18 上）

**依据**：
- phase 3 计算 kg（供 Kn 和 KgA）和 qg（供 Qn）时，要重读 k（每个 CTA 16 KB）和 fp32 的 g（32 KB）；
- 这两样 phase 1 已经按同样的 lane 分配（t = tid + 256·it）读过，而且同样的表达式已经算出了 kg（gkv）和 exp2f(g)（eg）；
- 分阶段计时显示 phase 3 基本受带宽限制：8K/96 时 0.96 ms，对应约 1.2 GB。

**改动**：
- phase 1 改为展开的 8 次迭代，把 kg 的 quad（16 VGPR）和 eg（32 VGPR）留在寄存器里；
- 默认路径（Kn 不为空）的 phase 3 只读 q，qg = bf_rne(bf2f(q)·eg)，kg 直接用寄存器里的值，表达式与原来逐字相同；
- wu 的占用率受 LDS 限制（每 CU 2 个 CTA，即每个 SIMD 2 个 wave，寄存器上限 256），多出约 48 个 VGPR 不影响占用率。

**预测**：

| 指标 | 预测 |
|---|---|
| 逐位一致 | 全部一致 |
| 每个 CTA 的读取量 | 少 48 KB（8K/96 时约 600 MB） |
| wu（相对 P-18） | 8K/96 快 6–10%，8K/12 快 8–13% |
| 算子总时间（相对 P-18） | 8K/96 快 0.8–1.3%，8K/12 快 0.8–1.5% |
| 资源 | VGPR ≤ 200，没有溢出，LDS 不变 |

**证伪条件**：算子快不到 0.4%，或任意形态变慢，或出现溢出。

## P-20：取消 aN_do 副本，s4b 在前段直接读行主序的 do（第 4 轮，结构改动）

**全局方向**（R15）：
- 第 3 轮之后重新做的三方对比显示，dAv 仍是同一块硬件上比例最大的缺口：FLA@BW / ours 在 8K/12 为 0.72，在 8K/96 为 0.56；
- 改法与 P-17 相同：取消布局副本，与 FLA 的数据流对齐。

**新基线上的消融**（R19，`dav_ablate.py`，只跑 dav）：

| 去掉的部分 | 8K/12（基线 208.5 µs） | 8K/96（基线 1976 µs） |
|---|---:|---:|
| aN_do 的分散写 | −25 µs | **−660 µs（−33%）** |
| A^T 的 16 次标量读 | −22 µs | −230 µs |
| pass 1 的 do 读 | −23 µs | −113 µs |
| Vn 暂存的读 | −31 µs | −98 µs |

aN_do 是 do 的 A 形式副本，唯一的消费者是 s4b。

**定价**（R12）：
- s4b 只在前段读一次这些片段（每个 lane 8 次 8 字节读），常驻在寄存器里，不在 kt 循环里；
- 改为从行主序的 do 读以后，每条读指令触及的行从 4 条变为 16 条，但每个 CTA 只有 8 次，而且不在递推链上；
- VGPR 已经到 256 的上限，**出现溢出就视为失败**。

**改动**：
- dav：`aNdo == nullptr` 时跳过这次写；
- s4b：`do_ == nullptr` 时，按 `ado[vt] = rok ? ld8(do_row + cb + ro + 16vt) : 0` 读入，行掩码与 dav 写 aN_do 时相同；
- 新的 C 接口 `g2_wy_s4_split_r` 增加 do_row 参数，旧接口 `g2_wy_s4_split` 保留，用于兼容 flash-train；
- 生产路径（S4=1、P4=3）启用，环境变量 `KDA_G2_NOADO=0` 可以恢复原路径。

**预测**：

| 指标 | 预测 |
|---|---|
| 逐位一致 | 全部一致（片段的值相同） |
| dav | 8K/96 快 25–35%（1976 降到 1300–1500 µs），8K/12 快 8–14% |
| s4b | 慢 0–2% |
| 算子总时间 | 8K/96 快 1.5–2.2%，8K/12 快 0.4–0.8% |
| 显存 | 反向少一个 aN_do 张量（[T,H,128] bf16） |
| 资源 | s4b 没有溢出，VGPR ≤ 256 |

**证伪条件**：8K/96 的算子快不到 0.8%，或任意形态变慢，或 s4b 出现溢出。

## P-22：两个递推 kernel 不再写 aN 副本，s4a/s4b 在寄存器里完成 4×4 跨 lane 转置（第 5 轮，结构改动）

**方向检查**：
- 同一块硬件上的缺口基本追平以后，剩下的是相对 A800 的差距；
- 新的水位分析（8K/12）显示：fwd_h_bn 和 dhu_bn 只用到 60% 的 CU，依赖链占 15–18%，访存发射 61–88%，属于并行度和延迟受限。这正是 TP8/TP4 这些最接近 A800 的配置的瓶颈；
- 这两个递推 kernel 每一步每个 lane 都要做 8 次分散的 2 字节写，分别是 aN(v_new) 和 aN(dv2)，唯一的消费者是 s4b/s4a 的前段，每个 CTA 只读一次；
- 原则与 P-17、P-20 相同：布局转换移到不在递推链上的消费者。这里的转换是 4 个共享同一行的 lane 之间的 4×4 转置，两次 32 位 shfl_xor 就能完成，不需要 LDS，也不需要 barrier。离线核对 0 处不一致。

**消融**（去掉这两次分散写，作为上界；带抖动的 A/B）：

| 形态 | v8o4 第 2 次 | dhu | 算子 |
|---|---:|---:|---:|
| 8K/12 | −16% | −12% | — |
| 8K/24 | 1.25 倍 | 1.13 倍 | 1.029 倍 |
| 8K/48 | 1.20 倍 | 1.05 倍 | 1.016 倍 |
| 8K/96 | 1.02 倍 | 0.90 倍（消融的伪影：用运行时条件关掉写入，会让 waitcnt 变保守，见 P-10） | 0.991 倍 |

**改动**：
- v8o4 增加 MODE 4（反向重算，只写 HbN 和 Vn，不写 ANv）；
- dhu v8b 增加 MODE 2（写 HbN，以及 C 形式的 dV2n，每步 2 次连续的 8 字节写，不写 ANv2）。v8b4 本来就是通用实例，不用改；
- s4b 的 avn 改从 Vn（C 形式）读后转置，s4a 的 dva 改从 dV2n（C 形式）读后转置；
- Vn 要保留到 s4，aN_vn 和 aN_dv2 不再分配，显存持平或略降；
- keep-state 路径中，前向保存的 aN_vn 继续使用；
- 环境变量 `KDA_G2_NOAN=0` 可以恢复原路径。

**预测**：

| 指标 | 预测 |
|---|---|
| 逐位一致 | 全部一致（值来自同一组寄存器，只是搬运方式不同） |
| v8o4 第 2 次 | 8K/12–8K/48 快 12–20%，8K/96 快 0–3% |
| dhu | 8K/12 快 7–11%，8K/24 快 7–11%，8K/48 快 2–5%；8K/96 在 −2% 到 +3% 之间（编译期实例，没有消融时的伪影） |
| 算子总时间 | 8K/12 快 1.5–2.5%，8K/24 快 1.8–2.8%，8K/48 快 1.0–1.6%，8K/96 在 −0.3% 到 +0.5% 之间 |
| 资源 | 4 个 kernel 都没有溢出，s4b 的 VGPR ≤ 256 |

**证伪条件**：8K/12 或 8K/24 的算子快不到 0.8%，或者 8K/96 慢于 0.5%。

## P-22a：只保留 P-22 中 v8o4 那一半（第 5 轮）

**依据**：P-22 的 A/B 加了显存位置抖动，没改的 kernel 两侧相差不到 0.2%，所以各个 kernel 的差异是真实的：
- v8o4 第 2 次（不再写 ANv）：快 1.07–1.24 倍，所有 H 都成立；
- s4b（转置的代价）：慢 1.7–3.2%；
- dhu 那一半（MODE 2 加上 s4a 转置）：H ≥ 48 时变慢，P-22 整体因此被证伪。

**按各 kernel 推算 P-22a 的净效果**（v8o4 第 2 次的收益减去 s4b 的代价）：

| 形态 | 净效果 |
|---|---:|
| 8K/12 | +37 µs |
| 8K/24 | +78 µs |
| 8K/48 | +113 µs |
| 16K/48 | +185 µs |
| 8K/96 | +5 µs |
| 32K/96 | 约 +480 µs |

**改动**：在 P-22 的基础上撤回 dhu 和 s4a 的部分：dhu 继续写 ANv2，s4a 的代码恢复原样。保留 v8o4 MODE 4，以及 s4b 从 Vn 转置。

**预测**：

| 指标 | 预测 |
|---|---|
| 逐位一致 | 全部一致 |
| 算子总时间 | 8K/12 快 0.6–1.2%，8K/24 快 0.8–1.4%，8K/48 快 0.5–1.1%，8K/96 在 −0.3% 到 +0.4% 之间 |

**证伪条件**：8K/24 快不到 0.4%，或者 8K/96 慢于 0.3%。

## P-22c：dhu 保留 aN(dv2)，但把分散写合并成线性的 8 字节写（第 6 轮）

**方向**：
- dhu 相对 A800 的效率缺口为 0.64–0.84；
- P-22 证明，直接删掉 dhu 的写入会让读取挤在一起发射（R21）。所以这次不删，只合并：
  - v8b 每个 lane 每步 4 次 2 字节分散写，合并成 1 次 8 字节线性写；
  - v8b4 每步 8 次，合并成 2 次；
- 合并后，每条写指令覆盖连续的 512 B；
- A 形式的 quad 从 kernel 已经暂存好的 vB tile 收集，放在原有的“vB ready”barrier 之后，每个 quad 需要 4 次 LDS 标量读，没有 bank 冲突；
- 下一步的 vB 写入在下一步第一个 barrier 之后，所以没有竞争。

**预测**：

| 指标 | 预测 |
|---|---|
| 逐位一致 | 全部一致 |
| dhu | 8K/12（v8b）快 3–7%，8K/24、8K/48（v8b4）快 2–6%，8K/96（v8b）在 −3% 到 +4% 之间（节奏有风险） |
| 算子总时间 | 8K/12 快 0.3–0.7%，8K/24 快 0.2–0.6%，8K/48 快 0.1–0.5%，8K/96 在 −0.3% 到 +0.4% 之间 |

**证伪条件**：8K/12 和 8K/24 都快不到 0.2%，或者任意形态慢于 0.3%。

## P-22d：dhu 的线性 aN(dv2) 写只在 CTA 数 ≤ 96 时启用（第 6 轮，按瓶颈类型分派）

**依据**：P-22c 的 A/B 带显存位置抖动，结果按 CTA 数明显分成两类：

| CTA 数（dhu 实例） | 形态 | dhu | 算子 |
|---|---|---:|---:|
| 48（v8b） | 8K/12、32K/12 | 1.07、1.20 倍 | 1.008、1.015 倍 |
| 96（v8b4） | 8K/24、64K/24 | 1.07、1.10 倍 | 1.006、1.009 倍 |
| 192（v8b4） | 8K/48、16K/48 | 0.98 倍 | 0.998 倍 |
| 384（v8b） | 8K/96、32K/96 | 0.80、0.90 倍 | 0.979、0.991 倍 |

- 与水位分析的瓶颈类型一致：CTA 数少时受延迟限制，只有 60% 的 CU 在忙，减少写指令能缩短每一步；CTA 数多时进入深度饱和，分散写起到让读取错开发射的作用（R21）；
- host 端本来就按 CTA 数在 v8b 和 v8b4 之间选择，这里沿用同一机制。

**改动**：
- 两个 dhu kernel 增加编译期参数 LIN：LIN 为真时使用 P-22c 的线性写，为假时保留原来的分散写；
- host 端在 CTA 数 ≤ 96 时选择 LIN；环境变量 `KDA_G2_DHU_LIN=0/1` 可以强制指定。

**预测**：

| 指标 | 预测 |
|---|---|
| 逐位一致 | 全部一致 |
| 算子总时间 | H=12 快 0.6–1.5%，H=24 快 0.4–0.9%；H=48 和 H=96 走的代码与基线相同，变化在 ±0.3% 以内 |

**证伪条件**：H=12 或 H=24 快不到 0.3%，或者 H ≥ 48 的变化超出 ±0.4%。
