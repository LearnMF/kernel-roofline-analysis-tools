# 拆分评估器（结构搜索第 1 步）：模型与历史回测（2026-10-13）

**目的**：对任何拆分改动（融合、消费者重算、去掉副本、改 CTA 几何），在动手前就预测出各 kernel 的时间。只有能把我们已经做过的实验结果复现出来，才用它给新候选排序。

**数据**：全部来自体检卡 `results/kda-ceiling-cards-20261013/cards.json`，即 16 个形态 × 每个生产 kernel 的实测：
- 时间、CTA 数、每 CU 驻留数、轮数、LDS 与 VGPR；
- 各资源的现指令流下限（HBM、TA、VALU、LDS、MMAC、链）；
- VMEM、VALU、LDS 指令数。

**脚本**：`examples/kda/decomp_eval.py`（`backtest` / `regimes`）。

## 模型（对每个实测 kernel 都能原样复现）

```
t = max( R · λ ,  F · imb · e )
```

- **R**：轮数 = ceil(CTA 数 ÷ (80 × 驻留数))。驻留数取以下各项的最小值：LDS 限制（每 CU 64 KB）、VGPR 限制（R38：每 SIMD 768 ÷ VGPR 个 wave）、每 CU 40 个 wave，以及 P-24 的限流。
- **λ**：每个 CTA 的延迟。R ≥ 2 时取 t ÷ R；只有一轮、但多个 CTA 共用一个 CU 的递推 kernel，取单独运行时的延迟，即同一 kernel 在 H=12 时的时间。
- **F**：各资源现指令流下限中的最大值。
- **imb**：最忙的那个 CU 决定总时间，imb = ceil(CTA 数 ÷ 80) ÷ (CTA 数 ÷ 80)。CTA 数不超过 80 时取 1。
- **e**：效率系数，按工作区间设定：
  - **受吞吐限制**：e 标定到使模型等于实测时间；
  - **受延迟限制**（gap > 1.2，且延迟项能解释实测时间）：e 取物理可达值 1.10。这样延迟一旦缩短，模型就能体现出收益。

**四种变换**：

| 变换 | 规则 |
|---|---|
| **merge**（同一 grid 的两个 kernel 融合） | λ 相加，因为一个 CTA 现在要执行两份指令流；各资源下限相加，再减去被消掉的流量；LDS 和 VGPR 按实际复用情况给定，重新计算驻留数和轮数 |
| **add_work**（消费者重算、增加写出） | λ 增加“指令数 × 每条的周期数”：VALU 8 周期、超越函数 16 周期、VMEM 按该 kernel 实测的平均周期；**递推链上每多一条写指令，加 205 周期**（用 P-50 标定）。各资源下限加上新增的需求 |
| **remove_bytes**（去掉读或写） | 各资源下限按字节比例减少；λ 减去这部分流量所占份额的一半（β = 0.5） |
| **geometry**（改每个 CTA 的宽度） | CTA 数和每个 CTA 的工作量按比例变化；重复读取的共享操作数按共享比例扣除 |

## 回测（比值 > 1 表示改动后变快）

| 实验 | 类型 | 预测 | 实测 | 结论 |
|---|---|---:|---:|---|
| B4b-lite：tail 融进 s4b（16K/12） | 融合 | 0.906 | 0.893–0.935 | ✓ |
| P-13b：l2n_apply 改为在消费者里重算（8K/12、8K/48） | 消费者重算 | 1.004 / 1.004 | 1.002 / 1.005 | ✓ |
| P-51：dhu 每个 CTA 处理 64 列（16K、32K、64K，H=48） | 改几何 | 0.833 | 0.84–0.89 | ✓（偏悲观 ≤6%） |
| F6：s4a + s4b 合成一个 kernel | 融合 + 容量 | LDS 61.8 KB，每 CU 只能放 1 个 CTA，轮数翻倍，0.51 | 放不下 / 更慢 | ✓ |
| P-49：递推每个 CTA 处理 64 列，16K/48 | 改几何 | 1.000 / 0.938 | 1.01 / 0.91 | ✓ |
| P-49，32K/48 | 改几何 | 1.111 / 1.111 | 1.12 / 1.02 | #1 ✓，#2 偏乐观 |
| P-49，64K/48 | 改几何 | 1.111 / 1.111 | 1.40 / 1.12 | 生产版存在 L2 颠簸，超出模型范围 |
| P-49，8K/96 | 改几何 | 0.833 / 0.833 | 0.90 / 0.68 | 方向对，#2 低估了损失 |
| P-53：h 片段复用，TP8（3 个形态） | 去掉指令 | 1.016–1.019 | 1.010–1.018 | ✓ |
| P-53，TP2 / TP1（3 个形态） | 去掉指令 | 1.000 | 1.018–1.056 | 低估：受吞吐限制的递推，去掉 LDS 读仍有小幅收益 |
| keep-state 前向的写（P-50 标定，完整 keep-state 检验） | 递推链上的写 | 140 / 280 µs | 140 / 262 µs | ✓（检验误差 7%） |

**结论**：
- **融合、消费者重算、占用率和容量这三类，全部对上**：方向全对，幅度误差在 30% 以内。下一步要评估的候选主要就是这几类。
- **改几何的预测较弱**：受吞吐限制时，共享读取的比例不好估；L2 容量效应也没有建模。所以对这类候选只给大致方向。
- **模型偏保守**：对受吞吐限制的 kernel，单纯缩短延迟时它预测“无收益”，实测往往还有 1–5% 的小收益。

## 16 个形态的工作区间（`regimes.txt`，直接由体检卡算出）

| kernel | 工作区间 | 对拆分搜索的含义 |
|---|---|---|
| s4a、s4b | **16 个形态全部受延迟限制** | 不适合作宿主：往里加任何工作都会拉长延迟（B4b 的根因）；但从里面拿掉工作，收益能直接兑现 |
| prep_a/b、gate、dav、bwd_tail、l2n_apply | 几乎全部受吞吐限制 | 作宿主时能吸收少量延迟；作为融合对象（guest）时，只有其中的访存流能真正被消掉才划算 |
| wu | 随形态变化：H=12、16K/96、32K/48 及以上受延迟限制，其余受吞吐限制 | 收益依赖形态，要分 TP 评估 |
| 递推（前向、重算、dhu） | H=12 受延迟限制（串行链）；H ≥ 24 受吞吐限制（多个 CTA 共用 CU） | 去掉单步指令的收益集中在 TP8（P-52、P-53 已验证） |
