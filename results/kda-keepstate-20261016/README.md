# keep-state 重测（2026-10-16，生产版 P-65，bw46 HCU1/2）

**测法**：用 `pipe_time.py`，在同一进程内每轮切换一次 `KDA_G2_KEEP_STATE=0/1`，测前向和前向+反向的 wall 时间。不开 checkpoint；12 轮取中位数。

| 形态 | 前向 k0 → k1 | 前向+反向 k0 → k1 | 收益 |
|---|---|---|---:|
| 16K/12（TP8） | 1769 → 2100 µs | 6674 → 6514 µs | **−2.4%（−160 µs）** |
| 64K/12（TP8） | 5725 → 6901 µs | 24154 → 23672 µs | **−2.0%（−482 µs）** |
| 16K/48（TP2） | 6005 → 7408 µs | 26572 → 26348 µs | −0.8% |
| 32K/48（TP2） | 11676 → 14123 µs | 52352 → 51665 µs | −1.3% |

**与 2026-10-13 的对比**：上次在生产版 7ff2524 上测得 TP8 快 4.5%，这次收益变小。原因是重算递推已从 537 µs 降到 443 µs（P-58 到 P-65），而前向递推多写 h、Vn、aN 的代价基本没变（16K/12 前向 wall 多约 330 µs）。

**显存**：k1 时前向为反向多保存 h（512 B）、Vn（256 B）、aN（256 B），合计每 token·head 多 **1024 B**，即从 520 B 增加到 1544 B（FLA 默认为 1032 B）。每层多出的显存：

| 形态 | 每层多出 |
|---|---:|
| TP8（H=12），16K | 16384 × 12 × 1024 B = **192 MiB** |
| TP8，64K | 768 MiB |
| TP2（H=48），16K | 768 MiB |

总量要再乘以“同时保存激活的 KDA 层数 × 在途 micro-batch 数”。

**默认模式 auto 已经部分用上了它**：在 Megatron 可重入的激活重算（CheckpointFunction）里，重算出来的前向会自动保留状态，只给本层的反向用，用完即释放，不会在层与层之间累积。所以在开全层重算的训练里，这 2–2.4% 的收益已经拿到，额外显存只是单层的瞬时占用（16K/TP8 约 192 MiB）。只有在不开重算、或用非可重入重算 / 激活 offload 时，才需要显式设 `=1`，这时显存会跨层累积。
