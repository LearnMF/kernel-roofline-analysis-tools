# dav 的 LDS bank 冲突（2026-10-13）——消融上限过低，不做

**起因**：分层 roofline 和 PMC 都显示，dav 平均每条 LDS 指令有 4.00 个冲突周期，是所有 kernel 里最高的（16K/12 和 16K/48 相同）。有分析据此估计 dav 能从 550 µs 降到 300–400 µs（8K/48）。

**冲突来源**（32 个 bank，每个 4 B，逐类核算）：

| 访问 | 情况 |
|---|---|
| 第一阶段暂存写（行距 132 个 short）、第一阶段矩阵乘读 | 无冲突 |
| dA 暂存写（行距 68 个 dword） | 2 路 |
| **第二阶段 do 转置暂存写** `slab[(vq+d)*68 + j]`（ds_write_b16，每个 lane 32 条） | 同一条指令中，lane 写入的行为 4k+d（k=0..31），行距 34 个 dword，bank = 8k+2d+常数：**32 个 lane 只落在 4 个 bank 上，8 路冲突** |
| 第二阶段矩阵乘读、dOT 回读 | 基本无冲突 |

**消融**（examples/kda/dav_ablate.py `noConf2`）：
- 改法：第二阶段的转置写改为每个 lane 写一个独立的 dword（`slab[((it*4+d)&7)*1024 + 2*tid]`），指令条数不变，完全无冲突。结果是错的，只用于计时。
- 测法：ab_kernels，每边 5 个进程，带显存位置抖动。

| 形态 | 生产版 | 无冲突 | 比值 |
|---|---:|---:|---:|
| 16K/TP8 | 279.4 µs | 272.9 µs | 1.024 |
| 16K/TP2 | 1088.6 µs | 1079.0 µs | 1.009 |

**结论**：冲突几乎都被隐藏了。dav 受 VMEM 发射（约 101%）和 HBM（约 75%）限制，LDS 冲突不在关键路径上。即使完全消除，整个算子也只快 0.04–0.1%。
- 可行的 swizzle 是 `列' = (j + 4·((v>>4)&3)) & 63`：读的一侧需要 8 字节对齐，列偏移只能取 4 个 short 的倍数，所以最多降到 2 路，收益还会低于上述上限；
- 因此不实现。

**规则 R42**：PMC 计数高（冲突、发射等）不等于时间代价。动手前先做消融：工作量不变，只去掉被怀疑的那部分开销，测出可能收益的上限。上限太低就直接放弃。
