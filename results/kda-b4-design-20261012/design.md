# B4：融合的按 chunk 并行梯度 kernel 设计说明（v0.1，2026-10-12，未写代码）

依据：第一性原理下限模型 `examples/kda/kda_bound.py`、设计评估 `design_eval.py`、TA 代价表 `ta_microbench.hip`、
递推与矩阵乘微基准 `bound_microbench.hip`，以及 P-45 的失败分析（R36）。本文只做设计和预算，用户审阅后才开始写原型。

## 1. 范围与目标

**取代的 kernel**（dense 与 varlen phase 2 两条路径）：

| kernel | 16K/TP8 | 16K/TP2 |
|---|---:|---:|
| s4a | 595 µs | 2969 µs |
| s4b | 1325 µs | 5943 µs |
| bwd_tail（含 reduce） | 709 µs | 2750 µs |
| head_gate（反向重算 fp32 门控） | 175 µs | 678 µs |
| l2n_apply（反向重算 qn/kn） | 156 µs | 629 µs |
| dav 中 dAqk 那部分输出 | 约 8% | 约 8% |
| **合计** | **2.96 ms** | **12.97 ms** |

**保留的 kernel**：wu、fwd_h_bn（重算状态 h 和 v_new）、dav（只保留 dhu 需要的 dVn / dOT）、dhu（dh 递推）。

**数值**：属于 B 类，按 bclass_gate 验收：FP64 精度不差于生产版、结果确定、Megatron loss 一致。原有路径保留为回退（环境变量开关）。

**目标**：
- 16K/TP8：2.96 ms → ≤ 1.0 ms（算子快 1.4 倍以上）；
- 16K/TP2：12.97 ms → ≤ 4.0 ms（算子快 1.5 倍以上）；
- 与 R 合并后，按 design_eval 预测，H20 默认配置 / ours 在 TP8 约为 1.4，在 TP2 约为 1.3。

## 2. 每个 chunk·head（64 个 token × 1 个 head）的输入输出

| 方向 | 张量 | 布局 | 字节 |
|---|---|---|---:|
| 读 | q、k（原始 bf16）+ rstd | 行主序 [T,H,128] | 32 KB + 0.5 KB |
| 读 | g_raw（bf16）、A_log、dt_bias | 行主序 | 16 KB |
| 读 | v（bf16，计算 dA 时用） | 行主序 | 16 KB |
| 读 | beta | [T,H] | 0.25 KB |
| 读 | do、v_new（Vn）、dv（dhu 的输出） | 原生分片布局（片主序连续） | 3 × 16 KB |
| 读 | h、dh（bN） | 原生分片布局 | 2 × 32 KB |
| 读 | T（Akk，前向保存） | 行主序 [T,H,64] | 8 KB |
| 写 | dq、dk、dg_raw、dv（bf16） | 行主序 | 4 × 16 KB |
| 写 | dbeta、dA_log / ddt_bias 部分和 | — | < 1 KB |
| **合计** | | | **读约 184 KB，写约 65 KB，即每 token·head 约 4.0 KB** |

**补充说明**：
- dAqk 在 kernel 内重算：dAqk = mask(do · v_newᵀ) · scale，每个 chunk 只需 0.5M 次乘加，不再读 dav 输出的 fp32 dAqk。
- 如果 l2norm 反向需要经显存周转 fp32 的 dq/dk（见第 5 节方案 D1），每个 chunk 再多读写 64 KB + 64 KB，每 token·head 共约 6.0 KB。

## 3. 计算阶段（按生产版 s4a / s4b / 收尾 / 门控 / l2n 的运算顺序）

| 阶段 | 内容 | 矩阵乘（每 CTA） | 主要 VALU |
|---|---|---|---|
| P0 前处理 | qn/kn = bf16(x·rstd)；门控 g = lb·sigmoid(A(g_raw+dt))，chunk 内 cumsum（并行扫描） | — | 每元素约 10 次 + 每元素 2 次超越函数 |
| PA（原 s4a） | dv2 = β ⊙ (Tᵀ dv)；dA（经 v）；pass W：dW = dv2·hᵀ（8 个 kt）；dA += dW·K̃ᵀ；dA 阶段：dAkk = −Tᵀ(mask(dA)β)Tᵀ | 约 300 条 16×16×16 | db 部分和 |
| PB（原 s4b，8 个 kt） | pass K：(v_new·dhᵀ)⊙2^(gn−g)；pass Q：(do·hᵀ)⊙2^g·scale；dkgb = Aᵀ(−dW)；块内表格（dAqk、dAkk 的三角乘积）；末端 dg 项 | 约 450 条 + mm8 | 每元素约 20 次（衰减、链式法则） |
| PC（原收尾） | dg：沿行逆序前缀和 + 门控反向 → dg_raw；dq/dk：l2norm 反向（整行点积，两遍）；dbeta | — | 每元素约 15 次 + 2 次超越函数 |

**VALU 预算**：现在这 5 个 kernel 的纯 VALU 合计约 35K 次/token·head。合并后 exp、门控、衰减各只算一次，目标不超过 20K。
- 以 16K/TP8、80% VALU 效率计，20K 次约需 0.64 ms，35K 次约需 1.1 ms。
- 所以 **VALU 去重是 B4 能否达标的关键之一**，不只是消掉字节。

## 4. 硬约束（来自实测）

1. **TA 代价**（每条 wave 级 VMEM 指令占用的 CU 周期，数据在显存中）：

   | 访问模式 | 读 | 写 |
   |---|---:|---:|
   | 行连续，每 lane 16 B（1 KB / 指令） | 21 | 56 |
   | 原生分片，每 lane 8 B 连续（512 B / 指令） | 22 | 28 |
   | 16 行 × 32–64 B | 85–169 | 64–67 |
   | 每 lane 一行的 gather | 229 | — |

   **规则**：行主序张量只允许按行连续访问，每行连续段不少于 256 B。分片布局的转换在 LDS 里做。
2. **VGPR**：每个 wave 最多 256 个，gfx936 没有可用的 AGPR。生产版 s4b 已经用到 236 / 253（dense / varlen）。
3. **LDS**：每个 CU 64 KB。每个 CU 放 2 个 CTA 时，每个不超过 32 KB。
4. **延迟隐藏**：每个 SIMD 至少要有 2 个 wave（R：F6、P-37 的经验）。可以是每个 CU 2 个 4-wave CTA，也可以是每个 CU 1 个 8-wave CTA。
5. **行主序的 q/k/g 要行连续访问，就得整行进 LDS**：
   - kt 分块只有 16 列，bf16 时每行只有 32 B，达不到 256 B 的连续段，所以 q/k 必须整行（每行 128 列，256 B）暂存；
   - q、k 合计 32 KB，再加门控（bf16 原始值 16 KB，或 fp32 累加值 32 KB）；
   - 这在每 CTA 32 KB 的预算里放不下，所以 **B4 只能是每个 CU 1 个 CTA（64 KB LDS）、8 个 wave**。

## 5. 候选组织方式与预算

**方案 D1：4 个 wave、每个 CU 2 个 CTA（沿用生产版组织）+ dq/dk 经显存周转**
- **访存**：q/k 按半行（64 列一批）暂存，每批 16 KB。
- **LDS**：表格 13 KB + h/dh 暂存 16 KB + 半行暂存，超出 32 KB；除非把表格和暂存区分时复用，但这会多出 barrier。
- **VGPR**：沿用 s4b 的结构，已接近 256，加门控和 l2n 的逐元素运算后很可能溢出（P-45 就是这样）。
- **预测**（16K/TP8，模型）：访存 1.0 ms（6.0 KB）、TA 0.32–0.38 ms、VALU 0.64–1.1 ms，约 1.0–1.1 ms。
- **风险**：VGPR 和 LDS 都放不下，P-45 已经部分证伪。

**方案 D2：8 个 wave、每个 CU 1 个 CTA、64 KB LDS、dq/dk 常驻寄存器（推荐的目标形态）**
- **分工**：
  - 8 个 wave = 4 个行块 × 2 个 V 半区；
  - pass K / pass Q 沿 V 的 128 维归约，两个 V 半区各做一半，每轮 kt 通过 LDS 交换一个 16×16 的 fp32 部分和（每个 wave 1 KB）；
  - 末端逐元素运算按列分给同一行块的两个 wave（每个 wave 负责每个 lane 4 列中的 2 列）。
- **VGPR**：
  - avn / ado 按 V 减半：每个 wave 各省 16 个；
  - dq/dk 常驻：每个 lane 16 列 × 2 = 32 个；
  - 其余常驻约 70 个，循环临时变量约 120 个；
  - 合计约 220–240 个，**需要原型验证**。
- **LDS**（64 KB）：

  | 用途 | 大小 |
  |---|---:|
  | q、k 整行（行连续读入、按 kt 切片读出，带 padding） | 2 × 16.5 KB |
  | 门控（bf16 原始值 16 KB，原地扫描成 fp32 累加值需要 32 KB；改为按 kt 现算） | 约 8 KB |
  | 块内表格 | 13 KB |
  | h/dh 分片 | 原生布局直接读进寄存器，不进 LDS |
  | V 半区交换区 + 进位区 | 4 KB |
  | **合计** | **约 58–62 KB，余量很小** |
- **预测**（16K/TP8）：访存 0.69 ms（4.0 KB）、TA 0.20–0.26 ms、VALU 0.64–1.1 ms，约 0.7–1.1 ms。16K/TP2 是 4 倍，约 2.8–4.4 ms。
- **风险**：
  - VGPR 和 LDS 的余量都很小；
  - 每个 SIMD 2 个 wave，能否像每 CU 2 个 CTA 那样隐藏延迟，需要实测；
  - PA（原 s4a）阶段在 8 个 wave 下的分工另需设计。

**方案 D3：渐进式，先拆成两个新 kernel**
- **B4a**：原 s4a + dAqk 重算，并接管 head_gate / l2n 的输出。
- **B4b**：原 s4b + 收尾，按 D2 的 8-wave 组织重写。
- **预测**：比 D2 多一次中间结果的显存往返（dwT / dA / db_part，约 0.6 KB/token·head），约 0.8–1.2 ms（16K/TP8）。
- **好处**：可以分两步验证，每一步都有单独可测的收益；B4b 就是 D2 的核心。

## 6. 推荐路径与止损线

**按 D3 → D2 推进。第一个原型是 B4b，即 8-wave 的 s4b + 收尾，使用行连续暂存和寄存器常驻的 dq/dk。**

**原型 1：B4b**
- **门槛**：
  - VGPR 不超过 256，不溢出；
  - LDS 不超过 64 KB；
  - B 类数值通过；
  - 9 个重点形态上，耗时不超过生产版“s4b + 收尾”的 0.75 倍（16K/TP8 合计 2.0 ms，目标约 1.5 ms 以下）。
- **止损**：如果寄存器放不下，或者耗时超过 0.9 倍，停止 B4。记录原因，转做“现有 kernel 的 TA 访存模式改造”和 R。

**原型 2：B4a**
- **门槛**：耗时不超过“s4a + gate + l2n + dav 的 dAqk 部分”的 0.8 倍。

**合并为 D2**：在两个原型都通过后进行。

## 7. 未决问题（原型阶段要回答）

1. **门控的 chunk 内 cumsum 放在哪里**：在 B4 里从 g_raw 重算（需要沿行的扫描，加上 LDS），还是由 B4a 写出 fp32 的 g 供 B4b 读（多读写 0.5 KB/token·head）。
2. **dv 的最终梯度从 B4a 写出**：dv2 经 β 与 Tᵀ 已在 PA 中算出，需要核对与生产版 dv 输出的对应关系。
3. **varlen**：chunk 末尾的无效行在扫描和点积中按 0 处理，沿用 P-45 已验证的做法。
4. **两个 V 半区交换部分和**：每轮 kt 多一次 LDS 往返和 barrier，对每轮的时长有多大影响。
5. **qn/kn 在 kernel 内用 bf16(x·rstd) 现算**：A 类等价已由 U3 证明，代价是每个元素一次乘法加一次 RNE。

## 附：R（递推 kernel 流水化）第一步的结论

- **前向递推的瓶颈**：SQTT（`g2_fwd_h_v8o4`，16K/TP8）显示，每个 SIMD 只有 1 个 wave 时，这个 kernel 卡在**指令发射**上：
  - 时间构成：发射 49.5%，发射延迟 29%，waitcnt 只占 17%，并不是在等访存。
  - 每步每个 wave 要发 436 条指令：

    | 指令 | 条数 |
    |---|---:|
    | 矩阵乘 | 56 |
    | f32→bf16 舍入（bfe + add3 + 打包） | 约 64 |
    | 16 位 LDS 标量写（h 与 v_new 的转置写回） | 32 |
    | exp2f 带范围检查的衰减（cmp / cndmask） | 约 48 |
    | 全局读 | 17 |
    | 64 位地址计算 | 约 30 |
    | 寄存器搬运 | 20 |

  - 每步 2.65 µs，同一依赖结构的微基准只要 1.23 µs。
- **P-46（波序号用 readfirstlane 变成 SGPR，地址计算移到 SALU）**：
  - 静态的 64 位地址 VALU 从 117 条降到 69 条；
  - TP8/TP4 下前向递推快 1.7–3.8%，但 TP2 下两个递推 kernel 都慢约 5%；
  - 整个算子在 −0.8% 到 +0.45% 之间，**否决**。
- **8-wave 旧版（`KDA_G2_R1A=0`）**：反而更慢（16K/12 为 1379 µs，对比 1198 µs），说明单靠“每个 SIMD 2 个 wave”不够。
- **结论**：要逼近 1.23 µs/步，必须把每步的读取和转换指令砍掉一大半；只调预取深度没有用。这项改造的收益上限约为 TP8 总时间的 4–6%，排在 B4 之后。
