# 项目 C：重新设计 s4b，与 bwd_tail 完整融合（立项于 2026-10-10）

## 目标

省掉 s4b → bwd_tail 之间 dq/dk/dg 的 fp32 往返，并合并 tail 的工作。

| 形态 | 流量上界（`kra.model.fusion --merge wy_s4_split+bwd_tail`） |
|---|---|
| 8K/H12 | 264 µs，占算子 6.3% |
| 8K/H48 | 1056 µs，占算子 6.9% |

前提：结果逐位一致；确定性保持不变。

## 约束：为什么一定要重新设计

- tail 中的 l2norm 反向是 `dx = r·dy − (dy·y)·y·r`，必须先得到**整行 128 列的点积**，才能写出这一行的任何一个元素；
- 现在的 s4b 是**列块在外层**：4 个 wave × 16 行，每个 kt 步每个 lane 产出 4 列。一个 lane 在 8 个 kt 步里总共持有该行的 32 列，同一行的 4 个 lane（q = 0..3）合起来覆盖 128 列；
- 所以每个 lane 必须把这 32 列的 dq（以及 dk）以 fp32 留到 kt 循环结束；
- **数值上可行**：tail 的点积是 lane 内两两相加，再做固定顺序的 shfl 树。s4b 的 lane 分布也能用同样的顺序重现，所以逐位一致不是障碍。真正的障碍是寄存器。

## 可行性探针（2026-10-10，`examples/kda/c_probe_s4b_rowc.py`，只编译、不跑）

在现在的 s4b 上把 kt 循环完全展开，让 dq（或 dq 和 dk）留在寄存器里，到最后再做行点积并直接写 bf16 的 dx：

| 变体 | VGPR | scratch 溢出（每 lane） | 结论 |
|---|---:|---:|---|
| 生产版 s4b（P-13 的 L2R 实例） | 250 | 0 | — |
| 留住 dq | 256 | **356 B** | 溢出 |
| 留住 dq 和 dk | 256 | **980 B** | 溢出。8K/H12 下 scratch 读写约 0.4 GB，超过它要省的 200 MB |

**结论：在现有 s4b 结构上增量修改不可行。** 这是先用探针检验设计、再决定投入的又一个例子（规则 R10）。

## 需要比较的新拆法（下一步：逐个做流量和寄存器的估算，再选一个做原型）

| 方向 | 思路 | 好处 | 要算清的代价 |
|---|---|---|---|
| C1. 8-wave 的 s4b，按列一分为二 | 每个行块由 2 个 wave 负责，各管 64 列。每个 lane 要留的列数减半（16 列 × 2 = 32 个 VGPR） | 寄存器压力减半；每个 CU 仍是 8 个 wave | 与列无关的状态（avn/ado 共 32 个 VGPR，dak/aqA/aqB/akB 约 44 个）每个 wave 都要一份；两个 wave 之间的行点积要经 LDS 交换 |
| C2. 行常量表放进 LDS | 把 dA/dAqk 表（每张 16 KB）从寄存器移到 LDS，腾出约 44 个 VGPR | 寄存器够用 | LDS 从 30.7 KB 增加到约 63 KB，每个 CU 从 2 个 CTA 变成 1 个，延迟隐藏能力下降 |
| C3. Q 路径和 K 路径拆成两个 kernel | s4b-Q 负责 dq 及其 l2norm 反向，s4b-K 负责 dk/dg | 每个 kernel 只需留一组数据 | 两者都要读 q/k/g；dg 同时依赖 Q 和 K 两条路径（`og = dg + qf·dqf + …`），需要一份 fp32 的部分和交接，会把一部分流量加回来 |
| C0. 只融合 dg 部分（方案 B） | 不碰 l2norm，只把 cumsum 和门控反向移进 s4b | 寄存器需求小 | 只拿到约 75 µs |

## 下一步

2. 对选中的方向做编译探针，看 VGPR 和溢出，再做随机数据的计时原型；
