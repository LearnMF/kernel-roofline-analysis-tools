# P-88：s4a/s4b 改为“head 维变化最快”的 grid 顺序（2026-10-17，bw47 HCU1，探针，结果逐位一致，尚未合入）

**来由**：三平台分析时发现，按每 12 个 head 折算，s4a/s4b 的耗时随 H 增大而上升，其他 kernel 基本不变。16K 下：

| H | 12 | 24 | 48 | 96 |
|---|---:|---:|---:|---:|
| s4a（µs） | 479 | 571 | 609 | 868 |
| s4b（µs） | 1306 | 1359 | 1259 | 1699 |

tail、wu、prep、dav 都基本持平。TP1 时这部分比线性多出 5.6 ms（16K）和 9.6 ms（32K）。

**假设**：原来 grid 是 dim3(NT, H)，chunk 维变化最快，同时驻留的约 160 个 CTA 都是同一个 head 的相邻 chunk。它们要读的数据覆盖 160 × 64 个 token、每行跨度 H·256 B，DRAM 行和页的访问分散程度随 H 增大。s4a/s4b 每条访存指令要碰 16 行、每行只取 32–64 B，所以对这种分散最敏感。

**做法**（`examples/kda/p88_s4_hf.py`）：`KDA_G2_S4_HF=1` 时改按 dim3(H, NT) 启动，kernel 按实际的 grid 顺序取出 (chunk, head)；H == NT 时两种顺序是同一个一一映射。每个 (chunk, head) 的 CTA 本来就互相独立，db_part 的归约顺序也固定，所以数值不变。

**门禁**：GATE_ALL PASS（8192:12、8192:48、**8192:96**，含 keep-state、gate-extreme、varlen），FI=3 PASS。

**结果**（同一进程内切换开关）：

| 形态 | wy_s4_split（s4a+s4b） | 前向+反向 |
|---|---:|---:|
| 16K/12 | 1825 → 1647 µs（1.108） | **1.028** |
| 16K/48 | 8636 → 7418 µs（1.164） | **1.068** |
| 8K/96 | 11419 → 7560 µs（1.510） | **1.165** |
| 16K/96 | 23309 → 15012 µs（1.553） | **1.188** |
| 32K/96 | 45778 → 30236 µs（1.514） | **1.169** |

**教训（R60）**：哪些 CTA 同时驻留，会决定 DRAM 和 TLB 的访问局部性，必须把 grid 顺序当成一个独立的调优维度。诊断时要看“同一个 kernel 按 head 数折算后的耗时是否随 H 上升”，单看一个形态是看不出来的。P-79 那批 kernel 内部的重排实验，碰不到这一层。

## P-89：把 head 维变化最快的 grid 推广到其它按 chunk 并行的 kernel——**否决**（`examples/kda/p89_hf_all.py`，bw46 HCU4）

门禁：所有开关同时打开时，GATE_ALL PASS（含 8192:96），FI=3 PASS。前向+反向（每个开关单独在同一进程内切换，比值大于 1 表示更快）：

| kernel | 16K/12 | 16K/48 | 16K/96 |
|---|---:|---:|---:|
| wu | 0.951 | 0.801 | 0.671 |
| dav | 0.971 | 0.895 | 0.861 |
| tail | 1.003 | 0.979 | 1.008 |
| prep（a 和 b） | 0.929（前向 0.814） | 0.800（前向 0.556） | 0.756（前向 0.445） |
| gate | 0.999 | 1.004 | 1.001 |

只有 s4a/s4b 能从 head 维变化最快的 grid 中受益；wu、dav、prep 反而大幅变慢，tail 和 gate 没有变化。所以 grid 顺序必须按 kernel 逐个实测（R60），不能一刀切。其它 kernel 保持 chunk 维变化最快。
