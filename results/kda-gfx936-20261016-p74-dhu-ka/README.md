# P-74：TP8 的 dhu 每个 CTA 只加载一次 KgA（2026-10-16，bw46，**不合入**）

**依据**：在 8-wave 的 v8b 中，(r1, v1=0) 和 (r1, v1=1) 两个 wave 每步都加载同一份 KgA，每个 lane 4 对 16 B，每个 CTA 每步约 80 KB 的读里有 32 KB 是这份重复。按 R54（TA 的占用随搬运的字节数变化），去掉重复预计可以缓解 dhu 46% 的 VMEM 发射受阻。

**改法**（`examples/kda/p74_dhu_ka_share.py`，模板参数 KS，只作用于生产版 LIN 实例且 4·nseg·H ≤ 80 时）：
- 两个 wave 各加载一半（kt 0–3 / kt 4–7），存进自己的 `kown`；
- 通过 LDS `kaS[r1][kt][lane]`（16 KB）交换：在预取的那一步结束时写入，在使用的那一步的屏障 A 之后读出，放进 `kpar`；
- GEMM-A 在用到时，按 kt 从 `kown` 或 `kpar` 中选取操作数，MMAC 顺序不变，逐位一致。

**第一、二版的坑（新规则 R55）**：
- 第一版用 `ka[4·v1 + j]` 按运行时下标访问，第二版改成 `if (v1 == 0) {…} else {…}`，两版都被编译器折叠成运行时下标的寄存器数组，数组被放进 scratch（`private_segment_fixed_size = 80`，循环里出现 25 条 buffer 访问），dhu 慢了 2.3–3.2 倍。
- 第三版改为两个独立数组 kown / kpar，并在用到时按位置选取，scratch 降到 0，VGPR 118。
- **R55**：寄存器数组的下标里只要混入运行时 wave 号（哪怕写成两个分支，也可能被编译器折叠），就会被放进 scratch。合入前必须检查 `.private_segment_fixed_size == 0`。

**结果**（第三版）：
- 逐位门禁 10/10，FI=3 PASS。
- A/B：第一次在 HCU 1/2 上测时，有其他用户的进程，64K 一组的离散度达 18–30%，数据作废。改在空闲的 HCU 6/7 重测：

| 形态 | dhu | 算子 |
|---|---:|---:|
| 16K/12 | 1.0035 | 0.9993 |
| 64K/12 | 0.994 | 0.9988 |

**结论**：每步少读 20% 的字节，dhu 没有变快。dhu 上已经试过三种做法，都没有收益：
- P-67：改用 4-wave 的去重版本，变慢；
- P-68：把写挪到预取读之后，变慢；
- P-74：KgA 只加载一次，持平。

所以 dhu 的“VMEM 发射受阻”既不受字节数限制（这些重复读大概率在缓存里命中），也不受读写顺序限制。按 8-wave 的 SQTT，单个 wave 每步在屏障上要等 400–1200 周期，dhu 更可能是被“最慢的那个 wave 加上 8 个 wave 的屏障同步”这条路径卡住。下一步要先对 dhu 做跨 wave 的关键路径分析（cp_step 的屏障跳转对 8-wave 同样适用），再决定怎么改。

## P-74 前后的 SQTT 关键路径（bw46 HCU7，TP8 16K/12，`cpdhu_r5_d1.txt` / `cpdhu_p74_d1.txt`）

| | 生产版 | P-74 |
|---|---:|---:|
| 每步周期 | 3563 | 3391（−5%） |
| VMEM 读发射受阻 | 925 | **341** |
| VMEM 写发射受阻 | 623 | 652 |
| GEMM-A 的 MMAC 依赖（`dep:mmac->mmac`） | 20 | 273（选取操作数的 `v_cndmask` 拉长了依赖链） |
| VALU 发射 + 等待 | 463 + — | 542 + 194 |

- 去掉重复读之后，链上的读受阻确实降了约 580 周期/步，但 GEMM-A 选取操作数的开销和写受阻抵掉了大半。单个 CTA 的步长只快 5%，而 kernel 的 A/B 时间没有变化。
- 现在链上最大的一项是**一条 `global_store_dwordx2` 每步在发射前要等 520–560 周期**（屏障 B 之后的 aN(dv2) 写）。原因推测是 TA 写带宽：写的每字节代价约是读的 2.6 倍。屏障 A 之后，8 个 wave 会集中发出 16 条 HbN 写，共 8 KB，大约要占 TA 450 周期；后面的读写都只能排在它后面。HbN 和 aN 都是必需的输出，字节数省不掉，能做的只有把这些写在整个步内**分散开发**。（P-68 把写整体挪到读之后，反而变慢。）
