# 第 13 轮（多余工作清单中的 A、B 两项），2026-10-13

## P-48 = 清单 B：收尾 kernel 阶段 A 改为相邻两列

- **改动**：每个 lane 负责相邻的两列（2l、2l+1），访问由 2 B / 4 B 改为 short2 / float2，阶段 A 的 VMEM 指令减半。
- **逐位一致的处理**：第一版两列一起算，编译器的 SLP 向量化把两列打包成 v_pk_mul / v_pk_add，原来的 fma 被拆成乘加两步，导致 dA_log 差约 1e-7。第二版（48b）把每一列的门控运算放进单独的基本块（用一个恒为真的不透明分支隔开），保持了生产版的 fma 融合方式。
- **结果**：19+3 组门禁全部逐位一致；收尾 kernel 快 1.02–1.07 倍，算子快 1.001–1.008 倍。第一版是 B 类，收尾快 1.06–1.11 倍；为保持逐位一致，放弃了约一半的收益。

## P-49 = 清单 A：递推每个 CTA 处理 64 列

- **改动**：新增 `g2_fwd_h_v8o4w_kernel`（NVH=4，每个 head 2 个 CTA），用于前向和重算。每一列的运算序列与原 kernel 完全相同，逐位一致。

**A/B 结果**（前向 #1 / 重算 #2 两个 kernel）：

| 形态 | 前向 #1 | 重算 #2 | 算子 |
|---|---:|---:|---:|
| 16K/48 | 1.01 | 0.91 | 0.995 |
| 32K/48 | 1.12 | 1.02 | **1.0085** |
| 64K/48 | **1.40** | 1.12 | **1.034** |
| 8K/96 | 0.90 | 0.68 | 0.972 |

- **为什么 64K 收益最大**：生产版的前向在 64K/48 下有 L2 颠簸，耗时 9.0 ms，超出线性外推（32K 时 3.6 ms，翻倍应约 7.2 ms）。原 kernel 有 192 个 CTA，每个 CU 最多放 2 个时坑位只有 160 个，同一个 head 的 4 个 slab 不能同时驻留，共享分块要从显存重新读。
- **为什么 NT 较小时变慢**：64 列 kernel 只有 96 个 CTA，分到 80 个 CU 上不均衡。
- **启用条件**：H ≥ 40 且 NT ≥ 512。
- **门禁**：22 组逐位一致，其中 32768:48 会启用新 kernel。

dhu 的耗时随序列长度线性增长（16K/32K/64K 下为 2.47 / 4.77 / 9.44 ms），没有 L2 颠簸；TA 利用率 59%，没有前向那么高。预计只有约 0.5% 的收益。

## F2 的关键原语微基准（lds_tr_microbench.hip）

| 读取方式 | 行距 272 B（256 B 加 16 B padding） |
|---|---|
| `ds_read_m32x16_b16`（转置读出分片） | 每条指令 16 个 CU 周期，与 ds_read_b128 相同，约 7.7 TB/s |
| ds_read_b64 | 每条 8 个周期 |

行距为 256 B 或 512 B（2 的幂）时有 2–4 倍的 bank 冲突。

**结论**：只要行距做了 padding，LDS 里的转置读取没有额外代价。因此“统一布局，由消费方经 LDS 转置读取”这条路，代价只在 LDS 暂存（空间和 barrier）上，不在转置本身。
