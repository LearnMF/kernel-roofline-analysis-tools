# 生产版 P-82b 的字节账目与每个 kernel 的上限（2026-10-16，bw46 HCU1/2）

**数据**：
- `raw/<T>_<H>/`：由 `examples/kda/ceiling/collect46.sh` 采集，包括 5 次 hip-trace、pmc read/write、L2 与 SQ 的自定义计数器、optrace；
- `raw/g2_ops_hip.s`：生产版源码的 ISA，由 `isa_g2_dbg.sh` 生成；`raw/isa_mix.json`：由它统计出的指令构成。
- 账目由 `examples/kda/byte_ledger.py` 生成（新增 `--pmc-iters 4 --trace-iters 9`，因为 kda_run 默认有 3 次 warmup；并把前向 MODE 5 也归到 fwd_h_o）。
- 每个 kernel 的上限由 `examples/kda/ceiling/cards.py` 计算（`KRA_CARDS_RES` 指向本目录）。

## 1. 字节账目：与 P-65 对比

| | P-65（10-16 早） | P-82b | 变化 |
|---|---:|---:|---|
| 16K/12 实测 HBM | 5075 MB（25812 B/th，**6.26 倍**） | 4873 MB（24784 B/th，**6.01 倍**） | −202 MB |
| 16K/12 各 kernel 时间之和 | 6364 µs | 5994 µs | −5.8% |
| 16K/48 实测 HBM | 20841 MB（6.43 倍） | 20447 MB（26000 B/th，**6.30 倍**） | |

省下的字节比预期少：
- 去掉的部分：l2n_apply 203 MB，重算递推 310 MB，wu 的 P1 布局 150 MB；
- 新增的部分：前向写 h 101 MB，wu 读 h 101 MB，prep_a 写 qn/kn 101 MB。

时间降得比字节多，是因为去掉的重算递推本身受访存延迟限制，省下的时间比它的字节量对应的更多。

## 2. 每个 kernel 的两层差距（16K/12；µs）

记号说明：
- floor = max(HBM 字节/峰值带宽，MMAC，实测的 TA/VALU/LDS 忙碌时间，递推单步链)，即这个 kernel 最忙的那项资源；
- iface = 按接口必需字节、理想 TA 代价得到的下限；
- **t − floor** = 最忙资源之外、没被掩盖的停顿；
- **floor − iface** = 做了多余的工作：TA 放大、多余字节、VALU 等。

| kernel | t | floor（限制项） | iface | **t − floor** | **floor − iface** | TA 放大 | 实测/接口字节 | VGPR / LDS / 每 CU CTA 数 |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| s4b | 1302 | 943（TA） | 586 | **359** | **357** | 4.49 | 1.33 | 236 / 32 KB / 2 |
| wu | 781 | 594（访存） | 511 | **186** | 83 | 1.75 | 1.18 | 220 / 26.9 KB / 2 |
| s4a | 568 | 373（访存） | 281 | **195** | 92 | 3.31 | 1.33 | 152 / 30.5 KB / 2 |
| prep_a | 657 | 517（VALU） | 287 | 140 | 230 | 2.64 | 1.45 | 152 / 21.5 KB / 3 |
| dhu | 660 | 572（TA） | 326 | 88 | 246 | 4.70 | 1.00 | 124 / 21 KB / 1 |
| tail | 622 | 577（TA） | 477 | 46 | 99 | 3.61 | 1.03 | |
| 前向递推 | 569 | 539（TA） | 318 | 30 | 221 | 4.60 | 1.00 | |
| prep_b | 354 | 310（TA） | 210 | 44 | 100 | 3.25 | 1.45 | |
| dav | 279 | 233（访存） | 231 | 46 | 2 | 1.99 | 1.01 | |

| **合计** | **5987** | **4834** | **3352** | **1153** | **1482** | | | |

16K/48 的合计：t 25752 = floor 19917 + 5835；iface 14076。t − floor 最大的几个是：
- s4b 1618；
- s4a 1038；
- dhu（4-wave 版）**910**，t/floor = 1.64；
- prep_a 594；
- wu 496；
- 重算递推 429；
- 前向递推 380。

注意：TA 忙碌里包含等数据返回的时间（R54 和规模扫描的结论）。所以两个递推的“TA 放大”有一部分其实是访存延迟，不全是访问方式本身的代价。

## 3. SQTT 诊断：s4a、wu、TP2 的 dhu（`sqtt/`，`diag83.sh`，生产版 P-82b，bw46 HCU1）

| kernel（形态） | 发射 | 访存等待 | 屏障 | 发射受阻 | 最大的一项 |
|---|---:|---:|---:|---:|---|
| s4a（16K/12） | 19.9% | **38.2%** | 10.9% | 31.0%（读 11.2%，写 8.3%） | pass W 每轮 kt 一次 `vmcnt(1)`（每 wave 7 次），占 **7.4%**：h 块和 kgB 只提前 2 轮预取，一轮 kt 的工作量（12 条 MMAC 加 4 次 LDS 写）掩盖不住访存延迟。另外每个阶段开头各有一次等待，每次 3–4%（A 暂存、dva、v 行、h/kg 的预热），都是“刚发出就要用” |
| s4a（8K/48） | 16.1% | **36.9%** | 12.5% | 34.5%（读 16.8%） | 同一处 pass W 等待占 **12.7%** |
| wu（16K/12） | 24.3% | **55.1%** | 6.0% | 14.6% | 每 wave 8 次 `vmcnt(1)`，占 **15.2%**：P-82 的 VNEW 用 bN 填 hB 时，每次读完马上就写进 LDS，访存延迟全部暴露 |
| dhu v8b4（16K/48） | **47.0%** | 9.5% | 4.8% | 38.7%（读 15.7%，写 9.9%） | 受发射和 TA 限制（VALU 370 万条），不是访存延迟 |

**dhu 在 H=48 的两个变体（同一进程内切换环境变量，dhu_bn 单 kernel 计时）**：

| | 16K/48 | 32K/48 |
|---|---:|---:|
| v8b4（4-wave，当前在 96–256 个 CTA 时自动选用） | 2323.7 µs | 4507.3 µs |
| **v8b（8-wave）** | **2182.2 µs（1.065）** | **4119.9 µs（1.094）** |
| 关掉 throttle（每 CU 2 个 CTA） | v8b4 0.862，v8b 0.860 | v8b4 0.804，v8b 0.800 |

当初 4-wave 的选用窗口（H=48 时快 4.6%）是 P-10 时期测的，后来 8-wave 版做过多轮优化，这个结论已经反转了。
