# P-59：前向递推直接算出转置后的 v_new（2026-10-14，探针，不合入）

**来源**：`step_whatif.md` 中模拟器排第一的递推单步候选。把 v_new 写入 LDS 的 `ds_write_b16` 换成 `ds_write_b64`，模拟器预测前向 MODE 1 快 7.6%、重算 MODE 4 快 4.8%。

## 做法（`examples/kda/p59_vt.py`，只改前向 modes 0/1/2）
- **GEMM1 对调操作数**：算 \(C' = h^\top W^\top\)，与原来的转置逐位一致。lane \((q_4, m)\) 持有 \(v = m\)、\(t = \text{B-lane}(q_4 + 4e)\)。
- **Wn 的 16 个 lane 按 pi16 重排**：prep_b 只改存储地址（零代价）。这样 B-lane \(n\) 拿到 W 的第 \(\pi_{16}(n)\) 行，每个 lane 的 4 个元素就是连续的 \(t = 4q_4 + e\)，写 vB[v][t] 只要一条 8 字节写。
- **Un 改成转置布局**：prep_b 用对调的 MMAC 计算 U，Ai 的行先用 `ds_bpermute` 按 pi16 重排。所有收缩顺序都不变，因此逐位一致。
- **MODE 2**：Vn/ANv 仍要旧布局，在 vB 屏障之后从 vB 读回。
- **范围**：反向重算（modes 3/4）读 wu 产出的 Wn/Un，不受影响。探针内前向不走 v8o4w。

## 结果
- **ISA**（MODE 1，每 wave 每步）：`ds_write_b16` 48→40，`ds_write_b64` 0→2，指令总数 599→597。prep_b 的 `ds_bpermute` +20。
- **逐位门禁**：**GATE_ALL PASS**（10/10，dense、varlen、keep-state、gate-extreme，第一次就通过）。
- **A/B**（bw52，5 进程 × 6 轮，比值 > 1 表示 P-59 更快）：

| 形态 | 前向 MODE 1 | prep_b | 算子 |
|---|---:|---:|---:|
| 16K/12（TP8） | 1.001（离散度 1.5% / 7.6%） | 0.993 | 1.000 |
| 64K/12（TP8） | 1.016 | 0.990 | 0.997 |
| 16K/48 | 1.008 | 0.990 | 1.000 |
| 8K/96 | 0.982（离散度 9.4%） | 0.996 | 0.999 |

## 结论
- **不合入**。前向递推的变化在 −1.8% 到 +1.6% 之间，都在离散度以内；prep_b 稳定慢约 1%，算子总时间不变。
- **模拟器高估了约 5 倍以上**（预测 7.6%）。它按每条 `ds_write_b16` 8 个周期的发射代价计价。推测（未用 SQTT 核实）这段发射被同一 CU 上其他 wave 的工作掩盖了，不在串行链上。这和 P-57 一样，属于“小幅收益模型批准不了”的情况。
- **新增规则 R50**：模拟器给出的收益如果来自**非关键路径上的发射代价**（LDS 写、地址运算这类可被其他 wave 掩盖的指令），先用 SQTT 确认这段指令确实落在串行链上，再写探针。对照：P-58 在 TP8（每 CU 一个 CTA）上有收益，推测是因为它去掉的 VALU 地址运算落在每步的依赖链上。
