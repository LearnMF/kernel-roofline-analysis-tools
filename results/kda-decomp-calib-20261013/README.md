## P1：驻留数曲线（结论 + "2→3"外推）

每档 = `KDA_PROBE_LDS_<k>` 把 kernel 总 LDS 顶到目标值迫使驻留数下降；5 进程，
配对差值（同进程 tag vs base）中位数；n=5。非配对跨进程噪声 ±10–19%（s4b/链），
配对后绝对偏差 ≤9pp（效应小的档位）。

**Δt vs 驻留数（paired-median，16K 两形态）**

| kernel | 档位 | 16K/48 | 16K/12 | λ@res1 |
|---|---|---|---|---|
| wu | 2→1 | +33% | +41% | ~22us |
| wy_s4a | 2→1 | +23% | +34% | ~22us |
| wy_s4b | 2→1 | +24% | +35% | ~43us |
| dav | 3→2 / 3→1 | +14% / +60% | +17% / +69% | ~16us |
| fwd_prep_a | 3→2 / 3→1 | +47% / +66% | +30% / +61% | ~44us |
| fwd_prep_b | 3→2 / 3→1 | +6% / +46% | +10% / +56% | ~19us |
| bwd_tail | 3→2 / 3→1 | +1% / +48% | +8% / +60% | ~34us |
| fwd_h 窄 | 3→2 / 3→1 | +4% / +4% | −4% / −5% | 链主导 |
| fwd_h 宽(32K) | 2→1 | ~0% | — | 链主导 |

**关键发现**：
1. **"λ 不变"假设被证伪但方式与预期相反**：对吞吐受限 kernel，λ=t/rounds 在低驻留
   时下降 ~3×（同驻 CTA 分摊发射/带宽）——真实行为是 t(res) 曲线，不是 R×常数λ。
   校准做法：用 t(res) 比例曲线（`lam_scale`），不要用固定 λ。
2. **链型 kernel（fwd_h/dhu）对驻留完全不敏感**（±5%）：时间是串行链路径，与
   CTA 打包无关——这与 P-49 宽版在 res1 也持平一致。
3. **s4a/s4b 2→3 外推**：实测最近的同构证据是 dav 3→2=+16.7%（倒数 ⇒ 2→3 约
   −14%）、prep_b +7~11%。s4b 同为发射受限、2→1 已示深流水线收益（+29~41%），
   **估 2→3 增益 ~13–15%**（dav 两形态 3→2 代价 +14~17% 的倒数；高于主 agent
   的 +6–9%，方向一致但幅度略大）。
   **前提是 LDS**：s4b 需从 32KB 压到 ≤21.3KB（VGPR 236 允许 3 驻留），s4a 需 ≤21.8KB。

## P2：寄存器压力曲线

s4b（生产变体 `<false>`，基线 VGPR=236）：

| N pins | VGPR | scratch | 主循环指令数 | 16K/48 t | 16K/12 t |
|---|---|---|---|---|---|
| 0 | 236 | 0 | 456 | 5952us | 1306us |
| 8 | 244 | 0 | 456 | 5947 | 1304 |
| 16 | 252 | 0 | 456 | 6031 (+1.4%) | 1333 |
| 24 | 256 | 16B | 491 | 6084 (+2.2%) | 1342 |
| 32 | 256 | 48B | 492 | 6214 (+4.4%) | — |

- **到 256 VGPR 上限之前免费**（n≤16：指令数不变）；越过上限编译器溢出：
  +35 条主循环指令 @+24 pins（≈1.4 条/pin），代价集中在 lds_read(+6)/waitcnt(+7)/valu(+20)。
- wu 基线 211 / s4a(AFS) 基线 152：+16/+32 pins 都在余量内，时间 0.0–0.2%（无溢出则免费）。
- **成本是双模态的**：余量内≈0；溢出段 ~+0.15–0.25%/pin 时间 + ~1.4 条主循环指令/pin。
- **P-55 复核**：P-55 的 s4b 主循环 456→499（+43 条）与 n≈30 的注入档一致——
  新增计算在序言期约 48 个常驻 VGPR 的压力正是这个量级（R46 机制确认）。

## P3：指令缓存

4 路径串行 FMA 探针（cyc/inst = t×1.5GHz / 每 wave 指令数）：

| footprint | 1 CTA/CU | 2 CTA/CU | 3 CTA/CU |
|---|---|---|---|
| ≤4KB | 8.6–9.5 | 16.7–18.4 | 24.7–26.5 |
| ≥16KB | 15.6–15.7 | 18.2–19.1 | 30.0–30.2 |

- 1 CTA/CU 时断崖在 **4KB→16KB 总 footprint**（≈1.8×）；2/3 CTA 时发射共享掩盖了断崖。
- s4b 生产版代码 = **4.8KB**（1200 条指令，`g2_calib_p2` 的 .s 实测）；P-55 按源码行数
  比例估 ~8.7KB——正落在断崖膝部。

## P4：L2 容量

体检卡 `req_rd`（接口必需读）vs `hbm_rd`（实测读）：

- 窄版递推（fwd_h_v8o4）extra = hbm_rd/req_rd − 1：H12/24 恒为 0；
  **H48: 0.14→0.44（8K→16K）**，H96: 0.31→0.52——同 head 4 个 CTA 共享 K 侧数据的
  复用距离随 T·H 增长，超出 L2(8MB) 有效窗口后共享读变 HBM 重读。
- 宽版（v8o4w，2 CTA/head）在 32K/64K 的 extra ≈ 0.02–0.38（H96 仍有）。
- 拟合：extra_lin = 0.0375·T_K + 0.00354·H − 0.33；λ 惩罚 = 1+0.21·max(0, extra_lin−1)。
  **对 P-49 64K/48 的解释：窄版在 64K 的 L2 颠簸使时间 +~26%，补上后预测 1.40 = 实测 1.40**。

## 模型项（`examples/kda/decomp_terms.py`）

| 函数 | 接法（给主 agent 的建议 diff） |
|---|---|
| `lam_scale(kernel, res_old, res_new)` | `merge`/`geometry`/`res_cap` 变化时乘在 `k.lam` 上 |
| `thr_cap(kernel, res_new)` | 同上：res 提高后吞吐项 e 的封顶修正 |
| `loop_inflation(kernel, d_live_vgpr)` | `add_work`/`merge` 后 `t() × factor`（机制税每条指令） |
| `icache_factor(code_bytes, n_paths)` | 同上：t × factor；code_bytes 取 kernel .s 指令数×4 |
| `l2_extra_hbm_bytes / l2_lam_factor` | `geometry`（宽窄变体对比）时乘在窄版 `lam` |

## 已知局限

- FWH_65 档（>64KB）非法：65KB 目标超过 LDS 上限导致全流崩溃，已废弃——
  宽版递推的 res=1 已由 33KB 档覆盖。
- dav 的 16K/48 档为补采（原批次被邻居 OOM 打断 + 一次 env 单位误填字节）。
- P1 只能往下压驻留数（LDS 补齐单向）；2→3 的外推依赖 3→2 档的斜率（dav/prep_a/prep_b
  有 3 档数据）。
- icache 净效应系数是用 P-55 单点回推的；探针只给出区间 [1.0, 1.8]。
- P-55 的 s4b_p55_bytes=8.7KB 是行数比例估计；P-55 复现树在 bw52，未取实际 .s。
- P4 的 λ 惩罚阈值（extra_lin>1 才罚）是启发式，32K/48 恰好不触发；
  如需更细的 L2 模型要做一个真正的合成探针（本任务标记为可选）。
