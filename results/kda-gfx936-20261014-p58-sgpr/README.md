# P-58：递推 kernel 的 wave 号声明为 wave 内一致，地址的公共部分放进 SGPR（2026-10-14）

**来源**：递推单步的假设实验（`results/kda-blocks-20261014/step_whatif.md`）。模拟器预测，去掉 64 位地址运算后，MODE 1 快 3.1%、MODE 4 快 9.0%。

**改动**（`examples/kda/p58_sgpr.py`，只改代码生成）：g2_fwd_v8.cuh 中 3 个递推 kernel 的 `wv = __builtin_amdgcn_readfirstlane(tid >> 6)`。

**ISA**：
- MODE 1 循环里的 64 位地址运算 30 → 14 条，VALU 73 → 67 条；
- MODE 4 地址运算 40 → 14 条，VALU 149 → 135 条；
- 两者的 SALU 都增加约 21 条（地址的公共部分改由标量单元计算）。

**逐位门禁**：10/10 PASS（dense 8192:12、8192:48 各含 keep-state 和 gate-extreme，varlen 两组各含 keep-state）。

**A/B**（每边 5 个进程，带显存位置抖动；比值 > 1 表示 P-58 更快）：

| 形态 | 前向 MODE 1 | 重算 MODE 4 | 算子 |
|---|---:|---:|---:|
| 16K/12（TP8） | **1.048** | **1.052** | **1.009** |
| 64K/12（TP8） | **1.034** | 1.013 | 1.004 |
| 16K/48（TP2） | 1.009 | **0.960** | 0.997 |
| 8K/96（TP1） | 1.001 | **0.906** | 0.994 |

**结论**：
- **TP8（每 CU 一个 CTA，受串行链限制）**：两个递推快 1.3–5.2%，算子快 0.4–0.9%。模拟器的预测在 MODE 1 上接近实测（−3.1% 对 −3.3% ~ −4.6%），在 MODE 4 上高估了（−9% 对 −1.3% ~ −5%）。
- **H 大的形态（每 CU 3–4 个 CTA）**：MODE 4 慢 4–9%。多出来的约 21 条 SALU，在多个 CTA 共用标量单元时成了负担。
- **合入方式**：按形态分派，只在 4H ≤ 80（每 CU 最多一个 CTA）时使用，做法与 P-22d、P-24 相同。这样只保留 TP8 上的收益，没有回退。
