# 递推单步的关键路径归因（2026-10-14，TP8 16K/12，SQTT）

**方法**（`examples/kda/blocks/cp_step.py`）：一个 trace 文件对应一个 CU 上的一个 CTA（TP8 每 CU 只有一个 CTA）。从稳态窗口（15%–85% 的步）末尾的屏障释放开始，**沿事件链往回走**，每条指令按下面的规则处理：
- **屏障有等待**：跳到最后到达的 wave，记 `barrier:sync`；
- **s_waitcnt 有等待**：重放按序的 vmcnt/lgkmcnt 队列，找到它实际等的那条访存指令，跳到这条指令的发射点，中间的时间记 `lat:<类别>`；
- **读 MMAC 结果的指令有等待**：跳到那条 MMAC，记 `dep:mmac`；
- **其他等待**：记 `stall:<类别>`（流水线或队列忙）；
- **没有等待**：前一条指令的发射周期在链上，记 `issue:<类别>`。

在跳转的阴影里发射的指令都不在关键路径上。采集脚本 `examples/kda/blocks/cap_rec.sh`，生产版是 g2_opt `82e00e7`（含 P-58d）。

## 1. 生产版的关键路径归因（每步周期数）

| 类别 | 前向 MODE 1（3618） | 重算 MODE 4（2495） |
|---|---:|---:|
| 显存读延迟 `lat:vmem-load` | **1394（38.5%）** | 81（3.2%） |
| LDS 读延迟 `lat:lds-read` | 311（8.6%） | **696（27.9%）** |
| VALU 发射 | 527（14.6%） | **650（26.1%）** |
| MMAC 发射 | 368（10.2%） | 260（10.4%） |
| LDS 写（发射 + 延迟 + 等待） | 381（10.5%） | 222（8.9%） |
| VMEM 发射受阻 `stall:vmem-load` | 330（9.1%） | 109（4.4%） |
| SALU、waitcnt、nop 等 | 307（8.5%） | 477（19.1%） |
| 屏障同步 `barrier:sync` | 约 0 | 约 0 |

- **前向 MODE 1**：38.5% 的关键路径是**一条显存读的延迟**。QgA 在屏障 A 之后立刻发射，约 150 条指令后就被 oh 的 MMAC 使用，中间没有别的工作可以掩盖。单步明细（`raw/mode1_step_listing.txt`）里，这条读发射后约 1150 个周期才返回。
- **重算 MODE 4**：没有单一的主导项，基本是发射受限。几块主要开销是：bN_emit 的 16 条 `ds_read_u16` 加 HbN 存储（约 420 个周期）、hB/vB 读的延迟、VALU 发射，以及 write_h 的 16 条 `ds_write_b16`。
- **这也解释了 P-59 为什么没有收益**：它改的 vB 写入发生在 QgA 等待期间，不在链上。

## 2. 据此做的 P-60：QgA/AqkA 提前一步发射（`examples/kda/p60_qg_prefetch.py`）
- **改法**：loadQg(i+1) 放在本步 oh 之后（qgf 最后一次使用），loadAq(i+1) 放在本步 o pass 之后。寄存器不变，VGPR 164→165。
- **范围**：只用于 MODE 1 的 SG 实例（4·nseg·H ≤ 80，即 TP8）。
- **逐位门禁**：GATE_ALL PASS（10/10）。
- **SQTT 复测**：MODE 1 每步 3618 → **2861** 周期（−21%），`lat:vmem-load` 从 1394 降到约 0；MODE 4 是对照组，没改，2495 → 2493。
- **A/B**（bw52，5 进程 × 6 轮，比值 > 1 表示 P-60 更快）：

| 形态 | 前向递推 | 算子 |
|---|---:|---:|
| 16K/12（TP8，启用） | **1.171**（633→540 µs） | **1.015** |
| 64K/12（TP8，启用） | **1.063**（A 侧离散度 11%） | 1.008 |
| 16K/48（不启用） | 1.001 | 0.999 |
| 8K/96（不启用） | 1.013 | 1.001 |

## 3. P-60 之后，前向 MODE 1 的关键路径（2861 周期/步）
VALU 发射 759（26.5%）、LDS 读延迟 609（21.3%）、MMAC 发射 379（13.2%）、LDS 写 450（15.7%）、SALU 211、VMEM 发射受阻 157。现在已经是**发射受限**。每个 wave 每步有 56 条 MMAC，按每条 8 个周期算，约 450 周期是 MMAC 的下限。

## 4. 按链上份额重排后的候选
1. **P-60 合入**：逐位一致，TP8 前向递推快 6–17%。
2. **write_h 的 16 条 `ds_write_b16` 合并成 4 条 `ds_write_b64`**（MODE 1 和 MODE 4 都在链上，每步约 300–400 周期）：
   - GEMM2 的 B 操作数是 Kn，把它的 16 个 lane 按 pi16 重排，C 片段里每个 lane 就持有连续的 4 个 k；
   - 生产方只改存储地址：前向在 prep_b，反向在 wu；
   - 收缩顺序不变，逐位一致。
   - 这和 P-59 是同一种技巧，但这次改的指令在链上。
3. **Ob 不经 oStage、直接存储**（MODE 1）：
   - 让核内 h、v_new 的 v 下标按 pi16 重新编号，o 的 C 片段里每个 lane 就持有连续 4 列，可以直接 8 字节写回 HBM；
   - 省掉 8 条 `ds_write_b16`、1 次 LDS 回读和一次 wave 内 lgkmcnt(0) 等待；
   - U 只要在 prep 里做同样的列重排（现在 Wn 用的 pm 技巧）。
4. **MODE 4 的 bN_emit 重构**（每步约 420 周期，16 条 `ds_read_u16`）。
5. **用 MMAC 代替 shfl 规约**（余果的提醒）：两个递推的步内没有 shfl，这一项只适用于 tail、s4b、prep 这些按 chunk 并行的 kernel，见第 5 节。

## 5. 用 MMAC 代替 shfl 规约：盘点与一个新构件
- **知识库里的例子**：
  - flash-attention MR #78（gfx938 FP8）：rowsum 改成和全 1 的 B 片段做 MMAC，替换 pk_add 加两级 `__shfl_xor`；
  - FlashKDA k1.md §5.3（gfx938 Neumann）：用 3 次额外 MMAC 换掉 C→A、A→B 的 wave 内重排。gfx936 上没有 LIT/LTS，对应的做法是对调操作数，以及用 lane 置换的置换矩阵。
- **生产 dense kernel 的 cross-lane 指令盘点**（`examples/kda/blocks/xlane_inv.py`，hipcc -S）：

| kernel | `ds_bpermute` | 用途 |
|---|---:|---|
| prep_b | 300 | 三角求解里的广播，不是规约 |
| bwd_tail | 192 | l2norm 反向：行点积的 6 级固定顺序树 |
| s4b | 168 | dgk 的 `msum` / `xsum16` |
| prep_a | 16 | l2norm 的平方和 |

  DPP 都是 0。gfx936 上编译器把 `__shfl` 一律降为 `ds_bpermute`。
- **新构件（实测）**（`examples/kda/blocks/mmac_sum_sem.hip`，`raw/mmac_sum_sem.txt`）：
  - **fp32 16x16x4 MMAC 的累加，就是从 c 开始、按 k 升序、每步按 fp32 舍入的顺序加法，65536/65536 行逐位一致。**
  - bf16 16x16x16 MMAC 的累加则不对应任何简单顺序，与“精确求和后只舍入一次”的结果只有 80% 一致。
  - 推论：用 fp32 K4 MMAC 配合 0/1 选择矩阵，可以**逐位复现**现有的固定顺序树。例如 `xsum16` 只要 2 次 MMAC，因为 C 片段 lane (q,m) 的元素 0 正好就是 K4 的 A 操作数布局。bf16 MMAC 做规约会改变数值，属于 B 类改动，需要 FP64 oracle 评估。
  - 有没有收益，要先对 tail/s4b 做关键路径分析，确认 shfl 在链上，再决定是否写探针（R50）。

## 6. 复测：生产版含 P-58d、P-60、P-61e（bw7 HCU4，2026-10-15）
`examples/kda/blocks/cap_b7.sh`，结果见 `raw/cp_p61e_d2.txt` 和 `raw/cp_p61e_d3.txt`。

| | 前向 MODE 1 | 重算 MODE 4 |
|---|---:|---:|
| 每步周期（P-60 之前 → P-60 → P-61e） | 3618 → 2861 → **2696** | 2495 → 2493 → **2319** |
| VALU 发射 | 677（25%） | 627（27%） |
| LDS 读延迟 | 605（22%） | **692（30%）** |
| MMAC 发射 | 387（14%） | 217（9%） |
| LDS 写（发射 + 延迟 + 等待） | 383（14%） | 159（7%） |

- **前向**：链上最大的一块是 **o 的 oStage 往返**。每个 v1a 依次是 4 条 `ds_write_b16`、一次 wave 内 lgkmcnt 等待、一条 `ds_read_b64` 回读，再做全局存储。这几步在链上合计约 300–450 周期：回读延迟 132+67，写延迟 77+67，外加写入发射和 bf16 舍入。其次是屏障 A 之后 GEMM1 的 hB 读延迟（140+100）。下一个探针是 **P-62**：核内 v 下标按 pi16 重新编号，o 直接写回显存。
- **重算**：链上主要是 bN_emit 的 16 条 `ds_read_u16`（共约 200 周期延迟），以及 GEMM1、GEMM2 的 hB/vB 读延迟。
